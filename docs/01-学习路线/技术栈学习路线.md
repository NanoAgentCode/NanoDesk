# NanoDesk 项目学习路线：由难到易

这份路线面向希望理解、维护 NanoDesk 的开发者。学习顺序从跨模块运行机制逐步收敛到单条接口、单个组件和基础工具；难度按需要同时理解的状态、模块和失败分支衡量。不是把旧目录倒序：每一阶段都围绕一个真实问题，给出源码入口、练习和完成标准。

源码核对基线：`74394fb`，版本 0.2.9。下列路径相对仓库根目录；实现变化后以当前源码和测试为准。

## 如何使用

先准备可运行的环境，再按阶段 1—8 阅读。每阶段先回答问题，再顺着入口追踪，只补当前遇到的语言知识。基础薄弱时可以临时查阅阶段 8，然后回到原阶段；不要求第一次读懂所有实现。

环境准备见[构建、配置与运维](../05-开发运维/构建配置与运维.md)。Windows 需要 Node.js、Rust、MSVC Build Tools 和 WebView2；从仓库根目录执行：

```powershell
npm.cmd install
npm.cmd run tauri dev
```

没有模型或外部服务配置时，仍可完成源码追踪与本地模拟测试；真实模型、OCR、MCP、SSH 操作留到具备测试环境后验证。练习使用独立测试目录和测试数据。

| 阶段 | 难度 | 核心问题 | 学习产出 |
| --- | --- | --- | --- |
| 1. 执行与恢复 | 最高 | 页面离开后，谁继续推进任务？ | 一次任务的状态与责任表 |
| 2. 调度与数据一致性 | 很高 | 重启、重试、删除如何避免重复或过期写入？ | 三种失败场景的恢复说明 |
| 3. 上下文与检索 | 高 | 模型本轮究竟看见哪些数据？ | 上下文来源与边界表 |
| 4. 协议与外部工具 | 较高 | 网络输出如何变成可靠事件和受控操作？ | 一条模型或工具调用记录 |
| 5. 宿主与 IPC | 中等 | 桌面与 CLI 如何共用业务能力？ | 一个命令的跨层契约表 |
| 6. 附件与展示 | 中低 | 一个文件如何进入会话并正确显示？ | 一种附件的生命周期说明 |
| 7. 前端组件与状态 | 较低 | 一次点击由谁保存、刷新和显示？ | 一项局部 UI 练习及验证 |
| 8. 语言与工程基础 | 基础 | 如何独立读代码、运行检查和定位错误？ | 可复用的本地检查清单 |

## 1. 执行与恢复：先理解完整任务

**目标：**解释聊天提交、流式输出、审批、工具执行、暂停与恢复之间的关系，区分前端显示状态和后端执行状态。

先读[后台任务执行器](../03-功能指南/后台任务执行器.md)、[任务中断与恢复](../03-功能指南/任务中断与恢复.md)和[任务规划与上下文压缩](../03-功能指南/任务摘要与上下文压缩.md)。

按职责阅读：

1. `src/hooks/useChat.ts`、`src/hooks/chat/executionRequest.ts`：找到会话、模型、项目目录和预算如何绑定到执行请求。
2. `src-tauri/src/agents/background_agent/commands.rs`、`executor.rs`：找到后台入口与持续执行循环。
3. `src-tauri/src/agents/agent_commands.rs`、`background_agent/planning.rs`：区分普通回答、规划、澄清和工具请求的处理。
4. `src-tauri/src/agents/background_agent/actions.rs`、`lifecycle.rs`、`lease.rs`：追踪用户决定、重启恢复和执行所有权。
5. `src/lib/backgroundAgent.ts`、`src/components/ChatPane.tsx`：看后端状态如何投影到当前会话，审批如何展示。

**练习：**追踪“在会话 A 提交文件任务 → 切换到 B → A 等待批准 → 回到 A 批准 → 工具完成”。用表格记录每一步的 run ID、conversation ID、状态、持久化位置与下一步触发者。再解释工具已经开始执行时关闭应用，为什么不能直接重做。

**验收：**能指出真正持有执行权的模块；能解释结果为何不会保存到 B；能区分普通回答无需规划、规划审核、工具审批，以及“工具结果未知”和“已失败”。从 `src-tauri/src/agents/background_agent/tests.rs` 找到相应测试证据，不把计划标记完成当作工具执行成功。

## 2. 调度与数据一致性：理解时间和失败

**目标：**掌握后台并发、持久化队列、事务、租约和过期结果屏障，而不只会调用数据库 CRUD。

先读[定时与事件任务](../03-功能指南/定时与事件任务.md)、[任务预算与通知](../03-功能指南/任务预算与通知.md)、[数据与存储设计](../02-架构设计/数据与存储设计.md)和[用户画像设计](../02-架构设计/用户画像异步批处理设计.md)。

分三条路径阅读，每次只追一条：

| 路径 | 源码入口 | 重点 |
| --- | --- | --- |
| 自动任务 | `src-tauri/src/agents/automation/schedule.rs`、`store.rs`、`worker.rs` | 触发游标、队列领取、重试、错过任务与结果未知 |
| 画像批处理 | `src-tauri/src/knowledge/profile.rs`、`src-tauri/src/storage/db/profile_store.rs` | 观察、组批、预算、租约、generation 与删除屏障 |
| 存储装配 | `src-tauri/src/app/bootstrap.rs`、`src-tauri/src/storage/db/storage.rs`、`schema.rs` | 四个领域库与 runtime、automation、observability 共七库；初始化和 schema 演进 |

**练习：**分别分析“每日任务错过三次”“画像请求发出后关闭全局记忆”“两个宿主同时尝试处理同一任务”。为每个场景记录：触发条件、数据库变化、谁能执行、是否重试、最终如何验证。通过源码和现有测试核对，先不改调度算法。

**验收：**能解释事务和进程锁分别解决什么问题；能区分任务执行预算与自然语言识别请求；能说明关闭开关、删除事实和停止网络请求不是同一件事。测试使用独立临时目录，避免不同用例共享目录级租约。

## 3. 上下文与检索：解释模型看到的内容

**目标：**区分当前消息、历史摘要、文档、项目索引、长期记忆和用户画像的来源、作用域与预算。

先读[提示词组装与预算](../02-架构设计/提示词组装与预算.md)、[Agent、RAG、MCP 与 Skills](../02-架构设计/智能体检索增强与扩展工具设计.md)和[文档右键对话](../03-功能指南/文档右键对话.md)。

阅读顺序：

1. `src/lib/chatSystemMessage.ts`、`src-tauri/src/agents/context.rs`、`context_budget.rs`：系统指令、动态上下文与历史压缩。
2. `src-tauri/src/knowledge/rag.rs`、`rag_retrieval.rs`、`document_insights.rs`：索引、召回与文档预处理。
3. `src-tauri/src/agents/background_agent/documents.rs`：具体问题与全文问题怎样选择处理路径。
4. `src-tauri/src/knowledge/code_index.rs`、`project_index.rs`：项目级索引与会话 RAG 的区别。
5. `src/lib/memoryLanguage.ts`、`src-tauri/src/storage/db/memory_store.rs`、`knowledge/profile.rs`：长期记忆识别、记忆召回与异步画像。

**练习：**为同一个问题填写“来源 → 作用域 → 读取入口 → 预算/截断 → 不可用时行为”表，至少包含短文档、长文档、项目索引、长期记忆、画像五行。再用测试文档分别提出一个定位问题和一个全文总结问题，记录走到的分支及使用的证据。

**验收：**能解释短文档直接使用全文、长文档分块及概要复用的差别；知道维护 FTS 表不等于检索正在使用 FTS；能区分记忆逐消息语义识别与画像异步批处理。全局开关关闭后的行为要从代码证明，不依赖界面名称推测。召回命中和模型回答正确需分别评估。

## 4. 协议与外部工具：处理不可靠输入

**目标：**理解协议适配、流式解析、超时与错误传播，以及工具执行前的权限检查。

阅读[模型服务集成协议](../04-模型接入/模型服务集成协议.md)和[模型服务接入指南](../04-模型接入/模型服务接入指南.md)，然后选择一条主线：

| 主线 | 源码入口 | 必须回答的问题 |
| --- | --- | --- |
| LLM 与 SSE | `src-tauri/src/integrations/llm/openai.rs`、`anthropic.rs`、`transport.rs` | 网络 chunk 为什么不是完整事件？如何识别结束、截断和空闲超时？ |
| MCP 与 Skills | `src-tauri/src/integrations/mcp.rs`、`skills.rs`、`src-tauri/src/core/plugins.rs` | 启用技能、连接服务、获得工具定义与获准执行有什么区别？ |
| Shell 与 Ops | `src-tauri/src/integrations/shell.rs`、`ops.rs`、`src/components/OpsPanel.tsx` | 进程/SSH 会话何时开始和结束？输出及错误如何返回？ |

三条主线都要回看 `src-tauri/src/agents/tool_policy/mod.rs`，确认路径、工具范围和风险判断。项目工作目录不构成完整 Shell 沙箱，MCP 工具描述也不替代权限校验。

**练习：**优先从现有本地模拟服务测试追踪“请求 → 分段响应 → 解析 → 事件 → 完成/失败”。若练习修复解析问题，先写失败用例，覆盖跨 chunk 字符或异常结束，再最小修改至通过。MCP/SSH 实测仅使用自己可控的测试服务。

**验收：**能区分传输失败、协议解析失败和业务拒绝；能指出日志/运行记录中的证据。模拟服务测试通过只证明相应协议分支，不代表真实供应商或远端服务已兼容。

## 5. 宿主与 IPC：把大系统收敛到一个命令

**目标：**从一个前端调用追到 Rust 处理与存储，并解释同一业务为什么能在无窗口 CLI 中执行。

先读[架构与模块设计](../02-架构设计/架构与模块设计.md)和[CLI 功能对齐](../05-开发运维/CLI功能对齐.md)。

阅读路径：

- 前端：`src/api.ts` 是聚合出口，具体封装在 `src/api/`；先选 `src/api/profile.ts` 或 `memory.ts` 中一个命令。
- 注册与类型：`src-tauri/src/lib.rs`、`src-tauri/src/storage/models.rs`，确认实际参数和返回类型所在文件。
- 宿主：`src-tauri/src/core/command_host.rs`、`src-tauri/src/cli/mod.rs`、`business.rs`。
- 契约生成：`scripts/generate-cli-business.py`、`docs/05-开发运维/cli-command-coverage.json`。

**练习：**为所选命令列出“UI 调用点 → TypeScript 参数 → IPC 名称 → Rust 参数 → 数据操作 → 返回值/错误”。使用 `nano --commands` 查看目录；用只读命令理解 `--call` 响应，再解释为何持续任务需要 `--serve` 保持进程存活。

**验收：**能区分前端类型检查和后端输入校验；能说明共享业务与窗口、托盘等桌面交互的边界。命令变更涉及注册或 DTO 时，知道同时核对前端契约、CLI 生成表及测试，而不是手工只改生成文件。

## 6. 附件与展示：追踪一个文件

**目标：**用一条可观察的文件链路理解批次处理、会话绑定、进度、失败与渲染。

从 `src/hooks/chat/attachmentBatch.ts`、`src/hooks/useChat.ts` 和 `src/hooks/useRagFiles.ts` 开始，再选择一种附件：

| 类型 | 继续阅读 | 输出与验证 |
| --- | --- | --- |
| 文档 | `src/api/documents.ts`、`src-tauri/src/knowledge/rag.rs` | 提取/索引状态、失败重试与原会话关联 |
| 图片 | `src-tauri/src/commands/images.rs`、`src/components/ImageAttachmentMessage.tsx` | 保存路径、预览、归档后仍能读取 |
| OCR | `src-tauri/src/services/ocr.rs`、`remote_ocr.rs` | 区分本地 PaddleOCR 与远程服务、识别限制和错误 |
| 音频 | `src/api/speech.ts`、`src-tauri/src/integrations/asr.rs` | 识别结果进入草稿，编辑后再发送 |

**练习：**在测试会话上传两种附件，让其中一个失败，记录成功结果是否保留、失败提示在哪里产生；切换会话后检查结果归属。图片在项目的 `.nanodesk/uploads/images/`，普通会话使用 app data 下 `temp/` 作为根目录，也保留该相对上传路径。

**验收：**能区分“文件保存成功”“可预览”“索引完成”和“OCR 成功”；能指出会话范围保护与批次清理位置。对照[OCR 说明](../03-功能指南/图片文字识别工具.md)和[ASR 说明](../03-功能指南/语音识别使用说明.md)核对外部依赖，不把附件上传成功当成模型能力验证。

## 7. 前端组件与状态：完成局部闭环

**目标：**读懂 props、state、effect、异步保存和错误显示，完成不牵动后端契约的小改动。

按由整体到局部的顺序阅读：

1. `src/WindowEntry.tsx`：主窗口、文档窗口与助手窗口的懒加载入口。
2. `src/App.tsx`、`src/hooks/useAppLayout.ts`：应用组合与布局状态。
3. `src/core/plugins.tsx`、`src/plugins/builtin.tsx`：主视图、设置页如何注册。
4. `src/components/settings/SettingsMemoryTab.tsx`、`SettingsProfileTab.tsx`、`SettingsProfileModelCard.tsx`：选项卡、开关与模型保存。
5. `src/theme.ts`：Mantine 默认主题与组件样式。

**练习：**先解释画像开关保存失败时为什么不能显示为已成功，再在练习分支调整一个局部说明文案或布局。若修复交互 bug，先用测试复现；只改直接相关组件，不顺手重构状态层。

**验收：**能说出状态的唯一来源和刷新时机；理解正在保存时禁用操作的原因。交互变更通过对应组件测试，并在页面检查成功、失败和加载状态；类型检查不能替代视觉和交互验证。

## 8. 语言与工程基础：形成独立工作习惯

**目标：**将前面遇到的概念落到语法和工具，能够自己查入口、运行检查、描述失败。

| 基础 | 在本项目中关注什么 | 小练习 |
| --- | --- | --- |
| TypeScript | interface、联合类型、可选字段、Promise | 从一个 IPC 返回类型推导 UI 必须处理的状态 |
| React | props、state、effect、回调与组件组合 | 解释一次状态更新为何触发渲染，何时需要清理 effect |
| Rust | 所有权、借用、Option、Result、match、`?` | 跟踪一个错误如何逐层传播到前端 |
| Serde / Tokio | JSON 字段映射、async/await、锁和任务生命周期 | 区分等待异步调用与启动独立后台任务 |
| SQLite | 参数绑定、事务、WAL、索引和迁移 | 找到一次写入的事务范围，不直接修改日常数据 |
| Vite / Tauri / Cargo | 前端资源、原生壳、Rust 编译和打包 | 区分前端构建成功与安装包可安装运行 |
| Git / 搜索 | 文件范围、差异、提交、`rg` | 只暂存练习涉及的文件，说明每处修改目的 |

常用检查，从仓库根目录执行，按修改范围选择：

```powershell
# 一个现有组件测试示例
npx.cmd vitest run src/components/settings/SettingsProfileTab.test.tsx

# 品牌检查、TypeScript 检查与前端生产构建
npm.cmd run build

# Rust 编译检查与库测试
cargo check --manifest-path src-tauri/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked

# 文本差异检查
git diff --check
```

打包和增量缓存机制见[模块化打包设计](../05-开发运维/模块化打包设计.md)。先学会区分各检查的作用，再按需要运行 `npm.cmd run package:win`；打包不作为每次文案练习的必做项。

**验收：**能给出“改了什么、为什么、运行了什么检查、仍未验证什么”的说明；遇到失败时能定位是类型、编译、运行、协议还是环境问题，不用一种检查的成功代替另一种。

## 完成路线后的综合验收

用一个可控的项目文件问答任务，提交一份学习笔记，包含：

1. 从 UI 提交到后台完成的入口与状态，说明切换会话时的行为。
2. 本轮上下文来源、数据范围和工具授权边界。
3. 一个失败分支及其持久化、重试或人工恢复路径。
4. 桌面与 CLI 共用部分，以及窗口交互的差异。
5. 实际执行的检查、结果和未覆盖的外部依赖。

能用源码和测试回答这些问题，才算完成项目级理解。没有必要为了证明学习完成而增加产品功能；后续真实开发先明确验收标准，修 bug 先复现，新增行为先写测试，再做最小实现。
