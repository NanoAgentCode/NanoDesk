# 任务摘要与上下文压缩

桌面主聊天页由左侧导航、中间聊天、右侧任务摘要组成。右侧可展开、收起，默认展开并在本机保存偏好；切换会话时读取对应摘要。沿用应用最小宽度 960px，较窄窗口的摘要区宽度缩小到 230px，收起后恢复聊天空间。

## 用户看到的内容

- 没有明确任务：显示“还没有明确的任务”，引导继续描述目标、问题或期望结果。不强制把闲聊、普通知识问答转成任务。
- 有明确任务：显示最多六条任务要点，包括主目标、已确认要求、关键结论和待确认问题。
- 任务进度、完成依据、阻塞和恢复位置仅用于内部交接，不作为右侧进度标签、百分比或看板展示。
- 用户可以直接在聊天中纠正摘要；本版不提供单独的摘要编辑器。
- 历史压缩摘要不再显示在聊天正文和归档预览中，原始聊天记录仍保留。

## 单主任务规则

一个聊天维护一条主任务。补充、纠正和临时插入问题不自动覆盖主任务；插入问题保留主线恢复位置。只有用户明确取消或替换目标时切换，存在歧义时保留主任务并询问。

助手建议不能当作用户确认，“先设计、不实施”等授权边界必须延续。完成事项应附执行结果或用户确认依据，不能把计划、尝试、执行成功和验证通过混为一谈。连续压缩时继承仍有效的目标、约束、待办和交接点，清除被新决定替代的旧要求。

## 更新与存储

后台聊天模型随正常回复在末尾返回 `<task_summary>` JSON 块。应用在流式输出时隐藏该块，只有完整、成功且未被中断的回复通过结构校验后才写入摘要。摘要不能代替普通回复。

内部字段：`main_task`、`items`（可见条目）、`constraints`、`completed`、`pending`、`blocked`、`resume`、`side_question`。每个列表最多八条，可见条目最多六条，每项最多 300 字。

摘要与回复原子保存到会话数据库，`task_summaries.message_id` 关联原回复并随消息删除级联清理。后续无更新、无协议块或协议无效时保留原摘要；内容无变化不新增摘要记录。重生成时没有有效新摘要则继承上次记录。会话切换与应用重启不会丢失已保存摘要。

模型下一次请求会收到最新内部交接记录，放在可选检索资料之前。前端通过 `get_task_summary_items` 只获取可见条目，并在消息变化、任务运行状态变化时刷新；过期会话请求不会覆盖当前会话。收起不停止后台更新。

## 与历史压缩的关系

任务摘要在普通回复结束后更新，不依赖达到压缩阈值。它复用当前模型响应，不额外发起一次模型请求，但会占用输入提示词和输出 Token。

历史压缩仍按上下文预算触发：旧历史生成结构化交接摘要，保留近期消息；摘要生成上限仍为 1,200 tokens。任务识别、阶段边界、完成依据、临时问题和主线恢复规则同时加入历史压缩提示词。system 上下文仍受原有预算裁剪约束。

该协议接入桌面后台聊天执行器；CLI 和定时任务不生成右侧任务摘要。已有会话在继续聊天并获得有效摘要后显示条目，不在打开历史会话时自动调用模型补生成。

## 验证与边界

- Rust 单元与存储测试：无任务状态、无效或截断协议、流式分片隐藏、会话隔离、重启持久化、重生成保留、删除清理。
- 本地模拟模型集成测试：真实 HTTP 流式响应经过后台执行器，摘要不进入聊天正文，并在下一步请求中携带内部交接记录。
- `scripts/tests/task-summary-ui.py`：使用真实 React 面板和模拟 Tauri IPC，验证空状态、条目、三栏布局、收起偏好、会话隔离、过期请求、错误重试和窄窗口。
- `scripts/tests/task-summary-app-ui.py`：加载实际主页面，在 1440px / 960px 下验证三栏、聊天原文保留、内部压缩摘要隐藏和右侧收起。
- 长历史集成测试额外验证压缩之后仍向模型传递主任务、授权边界和恢复位置。

模型是否准确理解主任务仍取决于模型能力，结构校验不能证明语义准确。未遵循协议或输出被截断时不会伪造摘要，而是保留上次有效记录；用户可在聊天中纠正。上述模拟测试验证程序链路，不代表对所有真实模型的语义效果评测。
