# 任务规划与上下文压缩

右侧原任务摘要区域改为任务规划，展示当前会话最新任务的目标、步骤、执行状态、完成数量与进度条，支持展开、收起和调整宽度。原来的条目摘要生成、保存和读取接口已移除。旧数据库记录保留，不再读取或用于模型提示词。

## 先规划、审核后执行

请求批准模式下，每次新任务必须先生成 task_plan。所有步骤在审核前显示为待执行，后台进入 awaiting_plan，暂停模型与工具执行。用户在右侧选择“批准规划并执行”或“拒绝执行”；拒绝会取消本次任务，可在聊天中提出新的要求。

审批绑定当前任务及规划内容。过期审批会被拒绝；更新目标、步骤顺序、步骤 ID 或标题后必须再次审核。进度和结果依据的更新不重复触发规划审核。每次新任务独立审批，不继承历史任务的许可。

规划批准不代替已有工具审批策略。请求批准模式下，文件、命令和外部工具仍需工具审批。帮我批准、完全访问模式保留原执行策略。

规划及审核记录存储在运行时数据库中，应用重启后保留待审核状态。审核等待不累计执行时间，不产生新的模型请求或工具操作。没有有效规划时后端拒绝进入执行流程，不依赖模型自觉停下。

## 步骤和进度

规划包含 goal 和 2 到 12 个 steps，每步包含 id、title、status 和可选 detail。标题应说明操作范围；detail 用于记录进度和结果依据。状态为待执行、进行中、已完成、已阻塞或已跳过，同时最多一个进行中。

右侧读取 list_agent_runs 中最新任务的 plan_json，定期刷新。完成进度只计已完成步骤，跳过步骤另行显示，不冒充完成。取消或失败保留最后进度，不自动将步骤标记完成。切换会话不会显示前一会话的规划。

## 上下文压缩

长历史的上下文压缩继续按预算触发，保留近期消息与结构化压缩记录。当前运行的规划独立注入模型上下文。旧 task_summary 块仅保留显示过滤，以兼容历史输出；不再生成或保存任务摘要。

## 验证

后端测试覆盖未审核无副作用、审批后执行、过期审批拒绝、规划变更重新审核、进度更新不重复审批、拒绝取消、重启保留待审核状态及缺失规划阻止执行。

步骤状态由模型根据执行结果更新，结构校验不代表对完成证据的语义验证。
