# 对话交付物

主窗口右侧任务面板包含“任务规划”和“交付物”两个选项卡。

## 分类依据

- **用户上传**：当前对话的文档附件和已发送的图片附件。
- **中间文件**：成功写入或执行命令后记录的产物，尚未被标记为交付；以及模型判断为完成本轮任务而编写的辅助文件。
- **最终交付**：模型结合本轮用户目标、历史上下文与文件用途明确标记的文件。后端验证文件确实位于工作目录内且存在，随后将角色与对应助手消息一起保存在 SQLite 元数据中。

新回复不再靠扩展名或 Markdown 链接决定最终交付身份。用户要求写转换脚本，脚本本身可以是最终交付；用户要求转换文档，辅助脚本通常是中间文件。旧回复没有分类元数据时，仍兼容已记录文件或项目文件清单中的 Markdown 链接。

## 多轮示例

如果第一次就要求生成 Word 文档，过程中临时产生的 `poem.md` 和 `convert.js` 都是中间文件，只有 `poem.docx` 是最终交付物。最先生成不意味着已经交付。

1. 用户要求“写一首诗到 MD”：`poem.md` 为最终交付物。
2. 用户后续要求“转为 DOCX”：`convert.js` 为中间文件，`poem.docx` 为最终交付物。
3. `poem.md` 保留其之前的交付身份，虽然它也是第二轮的输入；后续轮次不会自动将之前的最终交付降级。

分类从全部对话消息汇总，不只从最近 20 个运行历史中提取。重开会话后可恢复。每条模型回复通过隐藏的 `<deliverables>` JSON 清单声明角色；生成或修改尚未成功时不能声明交付。中断的回复不保存交付标记。模型未提供有效清单时不推测其意图，新产物暂列中间文件；不会把普通链接自动当成新的交付声明。模型分类仍可能出错，这不是对内容质量的自动验收。

## 产物记录与边界

命令执行前后在当前工作目录比较文件大小与修改时间，记录仍存在的新增或修改文件，不从命令输出猜测路径。成功命令的产物记录写入运行步骤元数据；失败命令不记录。扫描跳过控制目录、依赖目录和符号链接，最多检查 20000 个目录项、16 层目录，每次扫描最多 2 秒；无法完整扫描时跳过本次自动归集，不影响命令执行。模型仍可标记经验证存在的交付文件。

文件变化记录不是内容哈希证明，同目录中并发外部写入可能被归入本次变化。旧命令未保存产物记录，无法自动回溯归属；后续模型可在确认文件存在后重新声明交付。最终交付身份不等于保留每次文件内容快照，同一路径仍合并显示。

有本地路径的文件可点击文件夹按钮定位；文档附件由对话索引保存，没有原始路径时只显示名称。切换对话后只展示该对话记录。文件被外部删除或移动后定位可能失败，面板会显示错误。
