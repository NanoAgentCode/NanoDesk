# 任务中断、临时任务与主线恢复

## 使用方式

1. 执行中聊天输入区保持可用。直接发送“先检查这个报错，再把剩余实现改成新接口”等普通消息，即可打断并插入临时任务，无须特殊命令或弹窗。
2. 也可通过普通聊天发送“暂停任务”，随后补充要求；发送“继续任务”可恢复未完成任务。任务规划区的暂停、插入和恢复按钮作为快捷入口保留。
3. 应用先等待当前工具有确定结果，再进入独立的临时会话。原会话保留为暂停状态。
4. 临时任务成功完成后，应用自动恢复主任务。如果当前仍停留在临时会话，会自动返回原会话；在其他会话阅读时不会强制切换。
5. 恢复时同步临时请求和结果，更新未完成的主线步骤。连续插入的临时请求会按顺序传回主线，避免丢失后续补充要求。已完成步骤的 ID、标题、状态及证据保留。旧的待执行工具请求作废，必须根据新主线重新生成。

请求批准模式下，临时任务及主任务的新规划仍须审核，旧审批不能授权变更后的工作。临时任务失败或预算不足时不会默默视为完成，可先修复并继续临时任务，也可选择“结束临时任务并恢复主任务”。预算不足的主任务需调整预算后再恢复。

## 持久化与执行边界

- 暂停状态、恢复位置、主任务和临时任务关联保存在运行时 SQLite。应用重启不会清除完成进度；正在执行且结果未知的工具不会自动重放。
- 工具已经开始执行时，暂停会等待结果落盘。超过等待窗口会提示稍后重试，已提交的暂停请求仍有效。
- 完成临时任务后若应用恰好退出，启动恢复会检查尚未交接的完成记录。已恢复记录具有幂等标记；历史临时会话仍可返回主会话。
- 嵌套临时任务必须先处理最内层任务，不能绕过仍在执行的子任务恢复上层主线。

## 工具稳定性与代码搜索

- 优先使用代码索引给出的路径和行号，然后读取文件或搜索具体子目录。
- 允许 `rg -n pattern src/components`、`Get-ChildItem src-tauri/src -Recurse -Filter *.rs` 等明确范围的搜索；根目录、父目录及不确定路径的递归搜索被拒绝。规则也覆盖 `rg` 的默认递归、`git grep`、`find` 和 PowerShell `-Depth`。
- PowerShell 使用编码参数传递完整脚本，先完成语法解析、再执行，避免引号损坏及语法错误绕过 UTF-8 初始化。
- 自动或完全访问模式下，执行前的语法错误和搜索范围错误可要求模型重新生成调用，每个任务最多修正三次。真实执行失败、超时、未知副作用和 MCP 失败不自动重试。请求批准模式仍交由用户决定。
- 普通界面显示简短错误提示，完整诊断保留在默认折叠的错误详情中。
- 普通聊天中的暂停和继续不会重复创建任务；短时间重复按 Enter 只提交一次。后台控制消息保留给模型与运行记录，不作为普通聊天气泡展示。

## 验证入口

- `cargo test --lib background_agent::tests`：流式暂停、在途工具结果落盘、临时任务与主线更新、审批、失败恢复及修正上限。
- `cargo test --lib runtime::interruptions`：重启后暂停检查点和关联持久化。
- `cargo test --lib shell::tests`：Unicode、脚本语法错误及退出状态。
- `cargo test --lib tool_policy`：目录边界与根目录扫描拦截。
- `npm.cmd test`、`npx.cmd tsc --noEmit`：前端回归和 IPC 合同。
