# OCR 接入测试方案

## 完成标准

- 设置页可选择本地 PaddleOCR、外部 OCR API（OpenAI 兼容视觉接口）、自建 MinerU API，重启保留配置。
- 旧设置默认本地 OCR，保存 OCR 不覆盖 Tavily 和 ASR 配置。
- 外部 OCR 发送指定模型、Bearer 凭据和图片 data URL，提取文本；MinerU 上传 multipart 文件，兼容旧版和 V1 JSON 结果。
- 远程识别复用项目路径限制、图片类型和 8 MiB 大小限制；不静默回退本地服务。
- 配置不完整、HTTP 错误、空结果、任务失败和等待超时返回明确错误。

## 自动化验证

1. 前端 API 测试验证三种配置的加载、保存和错误传播。
2. Rust 测试验证默认配置、序列化往返、配置校验、响应解析。
3. 本地模拟 HTTP 服务验证真实请求（鉴权、模型、图片编码、multipart）、HTTP 失败及 MinerU 202 轮询。
4. 运行相关 Vitest、Rust 测试和前端生产构建。

## 手动联调

在设置 → 环境依赖保存配置，重启检查恢复；对允许的项目图片执行 `ocr_image`，分别检查本地 PaddleOCR、真实外部服务与自建 MinerU 的结果。真实服务联调需要可用服务地址、模型/权重及凭据，不以模拟测试替代。
