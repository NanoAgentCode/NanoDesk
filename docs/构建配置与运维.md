# 构建、配置与运维

## 1. 本地开发

安装依赖：

```bash
npm.cmd install
```

启动 Tauri 开发模式：

```bash
npm.cmd run tauri dev
```

前端单独启动：

```bash
npm.cmd run dev
```

前端构建和类型检查：

```bash
npm.cmd run build
```

Rust 检查：

```bash
cd src-tauri
cargo check
```

### 1.1 品牌配置

应用展示名、包名、桌面可执行文件名和兼容标识统一维护在根目录 `brand.config.json`。修改配置后执行：

```bash
npm.cmd run brand:sync
npm.cmd run brand:check
```

同步命令会更新 npm、Cargo 和 Tauri 的静态清单，构建与测试也会自动执行一致性检查。`bundleIdentifier`、`storagePrefix`、`projectDataDirectory`、`startupRegistryName`、CLI 注册表键和插件命名空间为兼容已有安装及数据保留，不能只为视觉改名而修改；如果确需修改，必须同时提供数据迁移。

### 1.2 LLM 生成参数

桌面端在“系统设置 → 供应商管理”中只保存供应商名称、协议、接口地址和 API Key，不再填写模型标识。模型路由打开时从各供应商实时获取模型列表，并根据供应商元数据和常见模型名称推断对话或嵌入用途。

### 模型路由

“系统设置 → 模型路由”统一管理固定模型列表、均衡/质量/速度/成本四种策略的指定模型、兜底模型和全局嵌入模型。所有选择项都来自“供应商管理”中实时获取并保存的供应商模型；选择时先选供应商，再选该供应商下的模型。固定模型列表可多选，用于限制固定模式下可直接选择的模型；四种智能策略各单选一个模型，同一模型可以被多个策略复用，未指定模型的策略不可直接选择。兜底模型在指定模型不适用、不可用或四种策略均无匹配项时使用。嵌入模型为单选，用于 RAG、项目索引和长期记忆向量化。

模型路由设置页提供以下模式：

- `固定模式`：直接使用当前会话选定的模型，不执行自动路由。
- `智能模式`：先识别通用、编程、推理、写作、翻译、总结或图片理解任务，再自动选择均衡、质量、速度或成本策略。
- `均衡模式`、`质量优先`、`速度优先`、`成本优先`：直接使用该策略指定的单一模型。

路由器使用本地确定性规则识别任务类型。智能模式按任务映射到首选策略：编程、推理、写作和图片理解使用质量优先，翻译使用成本优先，总结使用速度优先，通用任务使用均衡模式；若首选策略的模型未配置或其任务范围不匹配，则依次尝试其他已配置策略，最后使用兜底模型。直接选择某一种策略时，只检查该策略指定模型的任务范围，不匹配时使用兜底模型。每次路由会在界面提示任务类型、策略、模型组和实际模型，并把决定写入用户消息元数据。选中的实际模型会绑定到当前会话，保证后续 Agent 工具调用和继续生成使用同一模型。

模型路由模式、当前策略、固定列表、兜底模型及四种策略的单选模型保存在本机前端设置中；供应商连接、模型用途、任务范围和评分属性保存在配置数据库。升级旧版多选策略存储时，每种策略保留第一个仍然有效的模型；旧配置首次没有策略分配时，默认把第一个启用路由的对话模型分配给四种策略。嵌入模型选择会同步为兼容 ID `embedding-config`，因此现有 RAG、项目索引和长期记忆调用无需迁移。该功能不包含在线健康检查、动态负载、账号池或调用失败后的自动切换，连接不可用时仍按现有错误流程处理。

桌面端会话和 `nano` 终端客户端共用这些模型参数。用户画像提取、连通性测试和运维问答等内部任务仍可显式覆盖部分参数，以保持其确定性和输出规模限制。

## 2. nano 终端客户端

`nano` 与桌面端复用同一个 Rust LLM 实现、模型配置数据库、项目索引和会话存储。项目模式的对话会写入现有 `conversations/messages`，退出后可以恢复；`--temp` 模式仍只保存在当前进程内。

Windows 开发环境可单独构建并安装 CLI：

```powershell
npm.cmd run install:nano
```

默认桌面端发布构建不再生成独立 CLI 安装器。安装完成后请打开新终端，即可在任意目录直接使用：

```powershell
# 当前目录项目问答；启动时更新代码和文档索引
nano

# 恢复当前项目最近一次会话
nano --continue

# 获取会话列表、查看历史并按 ID 恢复（支持唯一 ID 前缀）
nano --sessions
nano --show 1234abcd
nano --resume 1234abcd

# 获取当前项目文件列表
nano --files

# 指定项目目录
nano --project D:\workspace\demo --continue

# 普通临时对话，不绑定项目
nano --temp

# 单次提问后退出
nano -p "这个项目的启动入口在哪里？"
nano --temp -p "帮我整理一个会议提纲"
```

交互命令：

- `/help`：查看交互命令。
- `/clear`：临时模式清空上下文；项目模式结束当前会话，下一条消息创建新会话。
- `/model`：查看可用模型。
- `/model add`：通过交互向导新增模型，保存后立即切换到新模型；已有项目会话会同步更新模型绑定。
- `/model <名称或 ID>`：切换模型。
- `/exit`：退出。

常用启动参数：

- `-C, --project <目录>`：指定项目根目录。
- `--temp`：普通临时对话。
- `--continue`：恢复当前项目最近更新的未归档会话。
- `--resume <会话ID>`：恢复当前项目指定会话，支持唯一 ID 前缀。
- `--sessions`：按更新时间列出当前项目可恢复会话。
- `--show <会话ID>`：查看当前项目指定会话的详情和全部历史消息，支持唯一 ID 前缀。
- `--files`：列出当前项目文件；遵循项目文件扫描的忽略目录、深度和数量限制。
- `-p, --prompt <问题>`：单次提问。
- `-m, --model <模型>`：按配置名称、模型名或 ID 选模型。
- `--no-index`：不在启动时重建项目索引，使用已有索引。
- `--data-dir <目录>`：覆盖桌面端应用数据目录。

CLI 默认读取桌面端 `com.nanodesk.desktop` 应用数据目录中的模型配置。首次交互式运行且没有聊天模型时，CLI 会依次引导选择 OpenAI/Anthropic 兼容协议，填写配置名称、接口地址、模型名称、上下文窗口和 API Key；API Key 使用隐藏输入，保存后的配置与桌面端共用。已有模型时也可以通过 `/model add` 运行同一类向导；新增成功后，当前 CLI 的模型列表会立即刷新并切换到新模型。非交互式调用不会等待输入，而是提示改用交互式 `nano` 或桌面端设置。

终端输出使用统一的语义配色：青色用于 NanoDesk 品牌和助手标识，蓝色用于字段标题，绿色用于输入提示和成功状态，黄色用于命令及警告，红色用于错误，弱化色用于补充信息。重定向输出、非终端环境、`TERM=dumb` 或设置 `NO_COLOR` 环境变量时自动关闭 ANSI 色彩。

项目模式会通过共享 Rust 索引器更新代码和文档索引；配置 `embedding-config` 后，CLI 与桌面端都会写入向量并使用相同的关键词/向量混合召回，Embedding 不可用时共同降级到实体或全文检索。项目会话与桌面端共用，恢复时默认沿用会话保存的模型，也可以通过 `--model` 或交互命令 `/model` 切换。临时模式不会绑定、扫描项目或写入对话历史。

CLI 当前复用的是模型配置、领域业务库、会话生命周期、项目文件列表、代码/文档索引与混合召回、普通记忆/画像基础上下文、上下文预算与滚动摘要，以及 LLM 流式请求；它不提供桌面端的 Agent 工具审批、MCP、Skills、RAG 附件或 Ops，也不打开 Agent runtime/观测数据库或初始化桌面端 `logs/` 日志。

仅构建、不安装：

```powershell
cargo build --release --bin nano --manifest-path src-tauri\Cargo.toml
```

## 3. Windows 打包

推荐命令：

```bash
npm.cmd run package:win
```

该命令执行 `scripts/build-installer.ps1`，流程包括：

1. 定位 Visual Studio Build Tools 的 `vcvars64.bat`。
2. 注入 MSVC x64 构建环境。
3. 调整 PATH，避免 Git for Windows 的 `link.exe` 抢占 MSVC linker。
4. 执行一次 Tauri release build，并仅启用 NSIS bundle。
5. 校验并输出标准 NSIS 安装包路径。

默认最终安装产物只有：

```text
src-tauri\target\release\bundle\nsis\NanoDesk_<版本>_x64-setup.exe
```

构建过程仍会产生 Tauri 桌面端可执行文件 `src-tauri\target\release\nano-desk.exe`，但不再执行独立 CLI release build、CLI 安装器打包、离线 NSIS 二次打包或 MSI 打包。标准 NSIS 在目标机器缺少 WebView2 Runtime 时可能需要联网下载。

Cargo 与 Tauri 的构建缓存包含工作区绝对路径。`package:win` 会在 `src-tauri\target\.nanodesk-workspace-root` 记录当前仓库路径；仓库被移动或目录改名后首次打包会自动清理旧 `target`，避免生成的权限清单继续引用原路径。路径未变化时会复用现有缓存。

如需 CLI，仓库开发者可单独执行：

```powershell
npm.cmd run install:nano
```

## 4. 应用数据与清理

运行时数据位于 Tauri app data 目录。主要文件：

Windows 默认位置为 `%APPDATA%\com.nanodesk.desktop`。

- `nanodesk-config.sqlite3`
- `nanodesk-conversations.sqlite3`
- `nanodesk-knowledge.sqlite3`
- `nanodesk-project-index.sqlite3`
- `nanodesk-runtime.sqlite3`
- `nanodesk-observability.sqlite3`
- `settings.json`
- `logs/`
- `skills/`
- `temp/`

清理建议：

- 排查业务数据问题时应一并备份四个领域业务库。
- 运行时记录异常膨胀时可考虑清理 `nanodesk-runtime.sqlite3`。
- 观测数据可在设置页清空，也可以删除 `nanodesk-observability.sqlite3` 后重启重建。
- `logs/` 中的系统操作日志按日期写入并自动保留 7 天，可用于排查启动和底层操作失败。
- `temp/` 是普通会话的临时工作目录，也可能保存普通会话图片附件；清理前确认是否还需要历史图片预览。

## 5. 配置项

### 5.1 通用设置

设置页的通用设置包含：

- 主题：浅色、深色或跟随系统，保存在 WebView `localStorage`。
- 关闭按钮行为：最小化到系统托盘或退出应用；“不再提示”也保存在 `localStorage`。
- Windows 开机自启动：通过当前用户注册表 Run 项 `NanoDesk` 管理。非 Windows 平台当前不支持启用。

项目入口、当前项目、Skills 启用状态与来源、Node/Python 路径等桌面 UI 状态同样保存在 WebView `localStorage`，不在领域业务库、runtime/观测库或 `settings.json` 中。

### 5.2 模型

聊天模型配置包括：

- provider
- base URL
- model
- API key

Anthropic 使用 Messages API；OpenAI、OpenRouter、Ollama 等走 OpenAI-compatible API。

### 5.3 Embedding

Embedding 配置独立于聊天模型，用于会话 RAG、项目代码/文档索引和普通手工记忆的语义召回：

- embedding provider
- embedding base URL
- embedding model
- embedding API key

独立设置保存为 ID 固定的 `embedding-config` 模型记录；该记录未单独填写 embedding URL 或 API key 时，会使用同一记录的聊天 `base_url` 或 `api_key`。只有会话 RAG 在找不到这条独立记录时会尝试当前聊天模型配置；普通手工记忆和项目索引不会跨记录回退。默认模型名为 `text-embedding-3-small`。

普通手工记忆会把启用记忆的标题、标签、正文和检索问题发送到该服务，向量只保存在本地知识库；服务不可用时降级到 FTS 和知识图谱召回。项目代码/文档索引也可在无向量时走实体或全文检索；会话 RAG 当前没有降级路径，索引和查询都要求 Embedding 服务可用。

### 5.4 用户画像

用户画像使用单独选择的聊天模型配置，不使用 Embedding 模型。启用后，本地先过滤持久化会话中的用户输入，再按阈值异步批量发送候选片段；设置页会显示实际模型名称、base URL、调用/字符预算和处理状态。画像事实、来源关系和任务状态保存在会话库，关闭功能不会删除已有事实，清空画像也不会删除聊天历史或普通手工记忆。

### 5.5 Tavily

Tavily API key 保存在 `settings.json`，用于可选互联网检索相关能力。

### 5.6 MCP

MCP 配置保存在配置库。stdio server 可以设置命令、参数、环境变量和工作目录；HTTP 类 server 可以设置 URL 和 headers。

### 5.7 Ops

Ops 服务器配置保存在配置库，支持 SSH 连接测试、文件上传和交互式终端。认证方式包括 SSH Agent、密钥路径和密码相关配置。交互式 session 只存在内存中，关闭应用或断开连接后不会持久化。

### 5.8 OCR

PaddleOCR 可通过环境设置页安装，也可以手动安装。若可执行文件不在 PATH 中，可设置 `NANODESK_PADDLEOCR_BIN`。

### 5.9 凭据保护

当前模型/embedding API key、MCP env/headers、Ops 密码和 Tavily API key 均没有应用层静态加密，分别保存在配置库或 `settings.json`。应限制 app data 与备份文件的访问权限；分享数据库、诊断包或日志前必须检查并移除敏感信息。

## 6. 观测与排查

观测系统默认记录部分关键类别，重点覆盖 LLM、MCP、Ops、部分工具和数据库操作。排查路径：

1. 在设置页打开观测面板。
2. 按 trace 查看同一次对话或操作的 span。
3. 检查 status、duration、operation、error 和 metadata。
4. 如需释放空间，可使用清空观测数据功能。

观测管线的原则是非阻塞：写入失败会打印错误，但不会让用户操作失败。

## 7. 安全检查清单

开发涉及工具执行或文件系统时，应确认：

- 是否使用真实 `project_path` 或明确的 `temp/` 根目录，而不是显示名拼路径。
- 是否通过相对路径归一化防止越界。
- 是否对写入、删除、命令执行保留用户确认。
- 是否避免把 API key 写入日志、观测摘要或错误详情。
- 是否避免把大型文件完整注入模型上下文。
- 是否让外部 MCP 工具结果以可见消息形式回到会话。
- 是否保留图片附件的 `.nanodesk/uploads/images/` 目录限制。

## 8. 推荐验证

普通前端、文档和类型相关改动：

```bash
npm.cmd run build
```

后端 command、数据库或模型链路改动：

```bash
npm.cmd run build
cd src-tauri
cargo check
```

打包路径改动：

```bash
npm.cmd run package:win
```

文档和小范围配置改动可以用 `git diff --check` 做轻量验证。
