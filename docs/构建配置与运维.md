# 构建、配置与运维

## 1. 本地开发

安装依赖：

```bash
npm.cmd install
```

启动 Tauri 开发模式：

```bash
npm.cmd run tauri dev
```

前端单独启动：

```bash
npm.cmd run dev
```

前端构建和类型检查：

```bash
npm.cmd run build
```

Rust 检查：

```bash
cd src-tauri
cargo check
```

### 1.1 品牌配置

应用展示名、包名、桌面可执行文件名和兼容标识统一维护在根目录 `brand.config.json`。修改配置后执行：

```bash
npm.cmd run brand:sync
npm.cmd run brand:check
```

同步命令会更新 npm、Cargo 和 Tauri 的静态清单，构建与测试也会自动执行一致性检查。`bundleIdentifier`、`storagePrefix`、`projectDataDirectory`、`startupRegistryName`、CLI 注册表键和插件命名空间为兼容已有安装及数据保留，不能只为视觉改名而修改；如果确需修改，必须同时提供数据迁移。

### 1.2 LLM 生成参数

桌面端在“系统设置 → 大模型”中按模型保存生成参数。`Temperature` 默认为 `0.4`；最大输出 Token 和 `Top P` 留空时不向 OpenAI 兼容接口传值，Anthropic 的最大输出 Token 留空时使用兼容层默认值 `4096`。`Reasoning Effort` 仅在 OpenAI 兼容协议下显示，只有支持该字段的推理模型才会生效。

桌面端会话和 `nano` 终端客户端共用这些模型参数。用户画像提取、连通性测试和运维问答等内部任务仍可显式覆盖部分参数，以保持其确定性和输出规模限制。

## 2. nano 终端客户端

`nano` 与桌面端复用同一个 Rust LLM 实现、模型配置数据库、项目索引和会话存储。项目模式的对话会写入现有 `conversations/messages`，退出后可以恢复；`--temp` 模式仍只保存在当前进程内。

Windows 用户安装方式：执行发布构建后，双击独立 CLI 安装器：

```text
src-tauri\target\release\bundle\cli\NanoDesk-CLI_0.1.0_x64-setup.exe
```

安装器按当前用户运行，无需管理员权限。默认创建 `%USERPROFILE%\.nano`，释放 `nano.exe`，并将该目录幂等写入用户级 `PATH`；卸载时会同时清理对应 PATH 项。安装或卸载后请打开新终端。安装完成后可在任意目录直接使用：

```powershell
# 当前目录项目问答；启动时更新代码和文档索引
nano

# 恢复当前项目最近一次会话
nano --continue

# 获取会话列表、查看历史并按 ID 恢复（支持唯一 ID 前缀）
nano --sessions
nano --show 1234abcd
nano --resume 1234abcd

# 获取当前项目文件列表
nano --files

# 指定项目目录
nano --project D:\workspace\demo --continue

# 普通临时对话，不绑定项目
nano --temp

# 单次提问后退出
nano -p "这个项目的启动入口在哪里？"
nano --temp -p "帮我整理一个会议提纲"
```

交互命令：

- `/help`：查看交互命令。
- `/clear`：临时模式清空上下文；项目模式结束当前会话，下一条消息创建新会话。
- `/model`：查看可用模型。
- `/model <名称或 ID>`：切换模型。
- `/exit`：退出。

常用启动参数：

- `-C, --project <目录>`：指定项目根目录。
- `--temp`：普通临时对话。
- `--continue`：恢复当前项目最近更新的未归档会话。
- `--resume <会话ID>`：恢复当前项目指定会话，支持唯一 ID 前缀。
- `--sessions`：按更新时间列出当前项目可恢复会话。
- `--show <会话ID>`：查看当前项目指定会话的详情和全部历史消息，支持唯一 ID 前缀。
- `--files`：列出当前项目文件；遵循项目文件扫描的忽略目录、深度和数量限制。
- `-p, --prompt <问题>`：单次提问。
- `-m, --model <模型>`：按配置名称、模型名或 ID 选模型。
- `--no-index`：不在启动时重建项目索引，使用已有索引。
- `--data-dir <目录>`：覆盖桌面端应用数据目录。

CLI 默认读取桌面端 `com.nanoagent.desktop` 应用数据目录中的模型配置。首次交互式运行且没有聊天模型时，CLI 会依次引导选择 OpenAI/Anthropic 兼容协议，填写配置名称、接口地址、模型名称和 API Key；API Key 使用隐藏输入，保存后的配置与桌面端共用。非交互式调用不会等待输入，而是提示改用交互式 `nano` 或桌面端设置。

终端输出使用统一的语义配色：青色用于 NanoDesk 品牌和助手标识，蓝色用于字段标题，绿色用于输入提示和成功状态，黄色用于命令及警告，红色用于错误，弱化色用于补充信息。重定向输出、非终端环境、`TERM=dumb` 或设置 `NO_COLOR` 环境变量时自动关闭 ANSI 色彩。

项目模式会更新共享数据库中的代码和文档索引，并与桌面端共用项目会话；临时模式不会绑定、扫描项目或写入对话历史。恢复会话时默认沿用会话保存的模型，也可以通过 `--model` 或交互命令 `/model` 切换。

CLI 当前复用的是模型配置、主业务库、项目文件列表、代码/文档索引、异步用户画像收集/Worker/上下文注入和 LLM 流式请求；它不提供桌面端的 Agent 工具审批、MCP、Skills、RAG 附件或 Ops，也不打开 Agent runtime/观测数据库或初始化桌面端 `logs/` 日志。

仅构建、不安装：

```powershell
cargo build --release --bin nano --manifest-path src-tauri\Cargo.toml
```

## 3. Windows 打包

推荐命令：

```bash
npm.cmd run package:win
```

该命令执行 `scripts/build-installer.ps1`，流程包括：

1. 定位 Visual Studio Build Tools 的 `vcvars64.bat`。
2. 注入 MSVC x64 构建环境。
3. 调整 PATH，避免 Git for Windows 的 `link.exe` 抢占 MSVC linker。
4. 构建 release 版 `nano.exe`。
5. 执行 Tauri build，生成桌面端 exe、NSIS 和 MSI。
6. 使用独立 Tauri 配置额外生成内置 WebView2 Offline Installer 的离线 NSIS 安装包，并保留原有标准 NSIS 安装包。
7. 使用 NSIS 生成独立的用户级 CLI 安装器。
8. 输出 CLI、CLI 安装器及桌面端各产物路径。

独立 CLI 安装器输出到：

```text
src-tauri\target\release\bundle\cli\NanoDesk-CLI_<版本>_x64-setup.exe
```

仓库开发者仍可运行 `npm.cmd run install:nano`，直接将当前源码构建出的 CLI 安装到 `cargo.exe` 所在目录；对普通 Windows 用户应优先分发上述独立安装器。

常见产物位置：

```text
src-tauri/target/release/nano-desk.exe
src-tauri/target/release/bundle/nsis/*.exe
src-tauri/target/release/bundle/msi/*.msi
```

桌面端 NSIS 目录会同时包含两种 `.exe` 安装包：

- `NanoDesk_<版本>_x64-setup.exe`：标准安装包，目标机器缺少 WebView2 Runtime 时需要联网下载。
- `NanoDesk_<版本>_x64-offline-setup.exe`：额外的离线安装包，内置 WebView2 Offline Installer，最终用户安装时无需联网，文件通常增加百余 MB，实际大小随微软提供的离线安装器版本变化。

离线配置位于 `src-tauri/tauri.offline.conf.json`，只在第二次 NSIS bundle 时合并，不改变默认 Tauri 打包配置、MSI 或 CLI 安装包。

## 4. 应用数据与清理

运行时数据位于 Tauri app data 目录。主要文件：

Windows 默认位置为 `%APPDATA%\com.nanoagent.desktop`。

- `nano-agent.sqlite3`
- `nano-agent-runtime.sqlite3`
- `nano-agent-observability.sqlite3`
- `settings.json`
- `logs/`
- `skills/`
- `temp/`

清理建议：

- 排查业务数据问题时优先备份 `nano-agent.sqlite3`。
- 运行时记录异常膨胀时可考虑清理 `nano-agent-runtime.sqlite3`。
- 观测数据可在设置页清空，也可以删除 `nano-agent-observability.sqlite3` 后重启重建。
- `logs/` 中的系统操作日志按日期写入并自动保留 7 天，可用于排查启动和底层操作失败。
- `temp/` 是普通会话的临时工作目录，也可能保存普通会话图片附件；清理前确认是否还需要历史图片预览。

## 5. 配置项

### 5.1 通用设置

设置页的通用设置包含：

- 主题：浅色、深色或跟随系统，保存在 WebView `localStorage`。
- 关闭按钮行为：最小化到系统托盘或退出应用；“不再提示”也保存在 `localStorage`。
- Windows 开机自启动：通过当前用户注册表 Run 项 `NanoAgent` 管理；这是为兼容旧版本保留的稳定标识，界面品牌名为 NanoDesk。非 Windows 平台当前不支持启用。

项目入口、当前项目、Skills 启用状态与来源、Node/Python 路径等桌面 UI 状态同样保存在 WebView `localStorage`，不在三份 SQLite 或 `settings.json` 中。

### 5.2 模型

聊天模型配置包括：

- provider
- base URL
- model
- API key

Anthropic 使用 Messages API；OpenAI、OpenRouter、Ollama 等走 OpenAI-compatible API。

### 5.3 Embedding

Embedding 配置独立于聊天模型，用于会话 RAG、项目代码/文档索引和普通手工记忆的语义召回：

- embedding provider
- embedding base URL
- embedding model
- embedding API key

独立设置保存为 ID 固定的 `embedding-config` 模型记录；该记录未单独填写 embedding URL 或 API key 时，会使用同一记录的聊天 `base_url` 或 `api_key`。只有会话 RAG 在找不到这条独立记录时会尝试当前聊天模型配置；普通手工记忆和项目索引不会跨记录回退。默认模型名为 `text-embedding-3-small`。

普通手工记忆会把启用记忆的标题、标签、正文和检索问题发送到该服务，向量只保存在本地主业务库；服务不可用时降级到 FTS 和知识图谱召回。项目代码/文档索引也可在无向量时走实体或全文检索；会话 RAG 当前没有降级路径，索引和查询都要求 Embedding 服务可用。

### 5.4 用户画像

用户画像使用单独选择的聊天模型配置，不使用 Embedding 模型。启用后，本地先过滤持久化会话中的用户输入，再按阈值异步批量发送候选片段；设置页会显示实际模型名称、base URL、调用/字符预算和处理状态。画像事实、来源关系和任务状态保存在主业务库，关闭功能不会删除已有事实，清空画像也不会删除聊天历史或普通手工记忆。

### 5.5 Tavily

Tavily API key 保存在 `settings.json`，用于可选互联网检索相关能力。

### 5.6 MCP

MCP 配置保存在主业务库。stdio server 可以设置命令、参数、环境变量和工作目录；HTTP 类 server 可以设置 URL 和 headers。

### 5.7 Ops

Ops 服务器配置保存在主业务库，支持 SSH 连接测试、文件上传和交互式终端。认证方式包括 SSH Agent、密钥路径和密码相关配置。交互式 session 只存在内存中，关闭应用或断开连接后不会持久化。

### 5.8 OCR

PaddleOCR 可通过环境设置页安装，也可以手动安装。若可执行文件不在 PATH 中，可设置 `NANO_AGENT_PADDLEOCR_BIN`。

### 5.9 凭据保护

当前模型/embedding API key、MCP env/headers、Ops 密码和 Tavily API key 均没有应用层静态加密，分别保存在主业务库或 `settings.json`。应限制 app data 与备份文件的访问权限；分享数据库、诊断包或日志前必须检查并移除敏感信息。

## 6. 观测与排查

观测系统默认记录部分关键类别，重点覆盖 LLM、MCP、Ops、部分工具和数据库操作。排查路径：

1. 在设置页打开观测面板。
2. 按 trace 查看同一次对话或操作的 span。
3. 检查 status、duration、operation、error 和 metadata。
4. 如需释放空间，可使用清空观测数据功能。

观测管线的原则是非阻塞：写入失败会打印错误，但不会让用户操作失败。

## 7. 安全检查清单

开发涉及工具执行或文件系统时，应确认：

- 是否使用真实 `project_path` 或明确的 `temp/` 根目录，而不是显示名拼路径。
- 是否通过相对路径归一化防止越界。
- 是否对写入、删除、命令执行保留用户确认。
- 是否避免把 API key 写入日志、观测摘要或错误详情。
- 是否避免把大型文件完整注入模型上下文。
- 是否让外部 MCP 工具结果以可见消息形式回到会话。
- 是否保留图片附件的 `.nano-agent/uploads/images/` 目录限制。

## 8. 推荐验证

普通前端、文档和类型相关改动：

```bash
npm.cmd run build
```

后端 command、数据库或模型链路改动：

```bash
npm.cmd run build
cd src-tauri
cargo check
```

打包路径改动：

```bash
npm.cmd run package:win
```

文档和小范围配置改动可以用 `git diff --check` 做轻量验证。
