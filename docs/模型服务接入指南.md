# NanoDesk 模型服务接入指南（使用方）

适用对象：配置 NanoDesk 的用户、部署人员和集成人员。覆盖 LLM、Embedding、OCR、语音转文字；以 2026-10-09 工作区实现为依据。服务端开发人员请阅读 [模型服务集成协议](模型服务集成协议.md)。

## 1. 接入前准备

| 能力 | 需要准备 | 在 NanoDesk 中配置的位置 |
| --- | --- | --- |
| LLM | OpenAI/Anthropic 兼容基础地址、密钥、聊天模型 ID | 供应商管理 → 模型路由 |
| Embedding | OpenAI 兼容基础地址、密钥、嵌入模型 ID | 供应商管理 → 模型路由 → 嵌入模型 |
| 语音转文字（ASR） | OpenAI 兼容基础地址、密钥、语音模型 ID、测试音频 | 供应商管理 → 模型路由 → 语音识别模型（ASR） |
| OCR | 本机 Python、PaddleOCR CLI、模型资源、测试图片 | 环境设置；在聊天中使用图片附件与 OCR 工具 |

NanoDesk 直接调用服务，不是向外提供这四类 HTTP API 的服务端。OCR 当前在本机运行，没有云端 OCR 地址或 API Key 配置入口。

向服务方确认 API 基础地址与模型 ID，并确认其提供模型列表接口。同一服务支持多种能力时，只建一个供应商；不同地址或密钥分别建供应商。模型 ID 是请求使用的标识，不能替换为任意显示名称。

## 2. 配置供应商并获取模型

1. 打开 **系统设置 → 供应商管理**，点击新建供应商。
2. 填写名称，选择“OpenAI 兼容协议”或“Anthropic 兼容协议”。
3. 填写基础地址和 API Key，点击创建/保存供应商。
4. 点击获取模型列表按钮，确认模型返回；在“模型路由”中选择具体模型和用途。

地址填写示例（示例域名需替换为实际服务）：

| 协议 | 应填写的基础地址 | 客户端实际访问 |
| --- | --- | --- |
| OpenAI 兼容 | `https://ai.example.com/v1` | `/v1/models`、`/v1/chat/completions`、`/v1/embeddings`、`/v1/audio/transcriptions` |
| Anthropic 兼容 | `https://claude.example.com` 或带 `/v1` | `/v1/models?limit=1000`、`/v1/messages` |
| 本地 OpenAI 兼容 | `http://localhost:8000/v1` | 相同的 OpenAI 兼容后缀 |

OpenAI 兼容地址不会自动补 `/v1`。不要填写完整的 `/chat/completions`、`/embeddings` 或 `/audio/transcriptions` 作为共用供应商基础地址，否则模型列表或其他能力可能拼出错误路径。

本地 LLM、Embedding、模型列表仅对地址含 `localhost` 的情况允许空密钥。使用 `127.0.0.1` 或其他地址且没有真实鉴权时，可按服务方约定填一个占位密钥，但服务必须接受该 Bearer 头。ASR 自身可匿名调用，模型发现仍受上述规则影响。

当前路由选择器依赖服务返回的模型或已有保存的模型记录。列表为空或模型用途错误时，先让服务方修正 `/models` 中的 `id` 与能力元数据；不要假定返回任意模型名称就能出现在所有选择器中。

## 3. 接入 LLM

1. 在 **系统设置 → 模型路由 → 固定模型列表** 中选择聊天模型。
2. 在聊天区选择固定模式及对应模型，发送“请回复：接入成功”。
3. 确认文字逐步显示、完整结束，再做一次多轮对话。
4. 需要智能路由时，分别给均衡、质量、速度、成本策略指定模型；每种策略当前对应一个模型，未配置的策略不可选择。兜底模型用于智能模式没有匹配候选的情况，不代表所有 HTTP 错误都会自动换模型重试。

如使用模型连接测试，应知道它发送一次非流式 `ping`；通过测试只能证明该请求可解析，不能替代聊天流式和 Agent 工具联调。

当前消息只发送字符串文本。供应商应支持 `/chat/completions` 或 `/v1/messages`；仅支持 Responses、原生 Ollama `/api/chat` 等不同协议的服务需要兼容层。图片文字识别走 OCR；不要把可上传图片等同于已经接入视觉模型。

## 4. 接入 Embedding

1. 添加提供 OpenAI 兼容 `/embeddings` 的供应商。
2. 打开 **系统设置 → 模型路由 → 嵌入模型**，选择对应供应商和嵌入模型；选择后自动保存。
3. 点击“测试嵌入连接”。
4. 上传一份小文档到聊天，完成索引后提问文档中的具体内容，检查检索结果。

Embedding 与聊天模型可来自不同供应商；Anthropic Messages 协议本身不能替代 `/embeddings`。客户端发送批量字符串数组，要求服务返回带 `index` 的浮点向量数组。

测试按钮只发一段 `ping` 并验证响应可解析，不充分验证批量数量、向量维度或检索质量。上线前应按服务方协议验证批量输入与真实检索。更换嵌入模型或维度后重新建立相关文档/项目索引，避免旧向量与新查询混用。

未配置或服务失败时，不同功能表现不同：普通记忆和项目索引有无向量降级路径；会话文档 RAG 的索引和查询依赖 Embedding 服务。需要稳定使用文档问答时，应显式配置全局嵌入模型。

## 5. 接入语音转文字（ASR）

1. 在供应商管理中添加 **OpenAI 兼容协议** 的语音服务。
2. 打开 **系统设置 → 模型路由 → 语音识别模型（ASR）**，选择供应商和语音模型；选择后立即自动保存。
3. “识别语言”留空表示不发送语言参数；服务支持时可填 `zh`、`en` 等两位代码，失去焦点后保存。
4. 点击“选择音频测试 ASR”，上传一段清晰音频，确认识别结果。
5. 在聊天区使用麦克风录音或回形针选择/拖入音频，检查文字进入输入框，编辑后点击发送。

ASR 使用供应商当前地址和密钥；修改供应商密钥后无需在 ASR 重填。删除所选供应商后需重新选择模型。旧版独立 ASR 设置仍可读取，新接入应使用供应商选择。

限制：

- 文件支持 WAV、MP3、M4A、MP4、MPEG、MPGA、WebM，单文件最多 25 MiB（界面标为 25 MB）；服务方可能有更小限制。
- 麦克风单次录音最多 5 分钟，转为 16 kHz 单声道 PCM WAV；文件上传保持原格式。
- 服务应在 120 秒内返回 `{ "text": "识别文字" }`，不支持只返回任务 ID 后轮询。
- 当前是整段转录，不提供实时字幕、说话人区分或长文件自动切分。多个文件按顺序追加结果。
- 取消或切换会话后不再把识别结果追加到当前草稿；已经发送的 HTTP 请求可能仍在服务端执行。

## 6. 接入本机 OCR

1. 在环境设置页检查 Python 与 PaddleOCR，按界面安装 OCR 依赖。也可在本机 PowerShell 手动执行：

   ```powershell
   python -m pip install --user paddleocr paddlepaddle
   ```

2. 确认 NanoDesk 能找到 `paddleocr.exe`。如果不在 PATH，可在启动 NanoDesk 前指定完整路径：

   ```powershell
   $env:NANODESK_PADDLEOCR_BIN = 'C:\实际路径\Scripts\paddleocr.exe'
   ```

   该变量需进入 NanoDesk 进程环境；在已经启动的客户端之外设置变量不会改变现有进程。测试路径请替换为实际安装路径。

3. 在聊天区添加图片，发送“请识别这张图片中的文字”，按当前应用访问模式批准 OCR 工具执行。
4. 确认返回图片上的实际文字；首次运行需准备模型资源，必要时下载完成后再测。

OCR 输入最多 8 MiB，支持 PNG/JPG/JPEG/BMP/WebP/TIF/TIFF；图片附件虽可保存到 25 MiB，超过 8 MiB 仍需压缩或裁剪才能 OCR。执行超时为 90 秒。

默认模型为 `PP-OCRv6_small_det` 与 `PP-OCRv6_small_rec`，在 CPU 上运行。项目图片保存在 `.nanodesk/uploads/images/`；普通会话使用应用数据目录下的 `temp/`。无需用户手工输入附件路径。

如必须使用云 OCR，需要单独提供并接入 MCP 工具，或开发远程 OCR 适配功能；当前不能在供应商管理里填写 OCR URL 实现该接入。完整依赖与排查见 [图片文字识别工具](图片文字识别工具.md)。

## 7. PowerShell 独立联调示例

这些请求直接测试服务，不能代替 NanoDesk 内的完整联调。示例只使用占位地址、密钥和模型名；从服务方获取真实值。以下示例面向 OpenAI 兼容服务，Anthropic 报文见 [服务方协议](模型服务集成协议.md)。

准备变量：

```powershell
$serviceBase = 'https://ai.example.com/v1'
$serviceKey = '替换为测试密钥'
$serviceHeaders = @{ Authorization = "Bearer $serviceKey" }
$chatModel = 'company-chat'
$embeddingModel = 'company-embedding'
$asrModel = 'company-asr'
```

获取模型：

```powershell
Invoke-RestMethod -Method Get -Uri "$serviceBase/models" -Headers $serviceHeaders
```

测试非流式 LLM：

```powershell
$chatBody = @{
  model = $chatModel
  messages = @(@{ role = 'user'; content = '请回复：接入成功。' })
  temperature = 0.4
  max_tokens = 256
} | ConvertTo-Json -Depth 6
$chatResult = Invoke-RestMethod -Method Post -Uri "$serviceBase/chat/completions" -Headers $serviceHeaders -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($chatBody))
$chatResult.choices[0].message.content
```

测试 SSE 流式 LLM（使用 `curl.exe`，避免 Windows PowerShell 的 `curl` 别名）：

```powershell
$streamBody = @{
  model = $chatModel
  messages = @(@{ role = 'user'; content = '请回复：接入成功。' })
  temperature = 0.4
  max_tokens = 256
  stream = $true
} | ConvertTo-Json -Depth 6 -Compress
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$streamBody | curl.exe --no-buffer "$serviceBase/chat/completions" -H "Authorization: Bearer $serviceKey" -H 'Content-Type: application/json' --data-binary '@-'
```

示例将管道输出编码设为 UTF-8，避免 Windows PowerShell 5.1 向 curl 传输中文时改变请求文本。预期逐步收到 `data:` 行，并在完成后结束连接；也需在 NanoDesk 中验证中文显示。

测试批量 Embedding：

```powershell
$embeddingBody = @{ model = $embeddingModel; input = @('第一段文本', '第二段文本') } | ConvertTo-Json -Depth 4
$embeddingResult = Invoke-RestMethod -Method Post -Uri "$serviceBase/embeddings" -Headers $serviceHeaders -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($embeddingBody))
$embeddingResult.data | Sort-Object index | ForEach-Object { "index=$($_.index), dimensions=$($_.embedding.Count)" }
```

预期恰好返回 index 0、1，维度相同且非零。ASR 文件上传：

```powershell
$audioPath = 'C:\实际路径\sample.wav'
curl.exe "$serviceBase/audio/transcriptions" -H "Authorization: Bearer $serviceKey" -F "file=@$audioPath;type=audio/wav" -F "model=$asrModel" -F 'language=zh'
```

不支持指定语言时去掉最后一个 `-F`。不要手工指定 multipart 的 Content-Type/boundary，让 curl 自动生成。预期返回顶层非空字符串 `text`。

## 8. 常见问题与验收

| 现象 | 检查方法 |
| --- | --- |
| 模型列表 404 | 基础地址是否已含版本前缀；是否误填了完整功能接口；服务是否实现 `/models` |
| 模型找不到/在错误类别 | 确认模型列表的 ID、capabilities/type/task；让服务方按协议补齐用途 |
| 401 / 403 | 密钥、模型权限、供应商协议类型以及网关鉴权方式 |
| 对话测试通过，聊天无输出 | 另测 `stream: true`；检查 SSE `data` 结构、网关缓冲与响应结束 |
| 参数不支持 | 检查服务是否接受 temperature、max_tokens 等；由兼容网关转换 |
| Embedding 能测通，检索异常 | 检查批量数量、index、维度、是否换模型后仍使用旧索引 |
| ASR 413 / 429 | 服务方大小限制、额度、并发或调用频率 |
| ASR 没有文字 | 音频是否清晰；响应是否是顶层非空 text；纯文本/SRT/异步任务响应不兼容 |
| ASR 超时 | 使用更短音频并检查网络、服务处理时间；客户端限时 120 秒 |
| 麦克风不可用 | Windows 麦克风隐私权限及桌面应用访问权限 |
| OCR 未检测到/执行失败 | 环境检测、CLI 路径、模型资源和原始错误；用 raw 输出排查 |

密钥保存在本机配置库，当前没有应用层静态加密；备份、分享配置或联调截图时避免包含真实密钥。远程模型请求会把相应文本或音频发送给所选服务；OCR 在本机执行。

完成接入需确认：模型列表可用、聊天逐步输出且结束、真实文档索引和问答成功、实际音频识别成功、测试图片提取到文字，并记录服务地址、模型 ID、测试日期与结果。本文示例已作结构检查，未使用真实密钥或外部服务执行生产联调。
