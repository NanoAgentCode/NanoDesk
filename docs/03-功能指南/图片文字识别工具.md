# OCR 工具

NanoDesk 提供 `ocr_image` Agent 工具，用于从项目图片中提取文字，可选择本地 PaddleOCR、外部视觉 API 或自建 MinerU。默认使用 PaddleOCR PP-OCRv6 small；其模型文件不会打包进主程序，由用户本机 Python 环境准备或下载。

OCR 策略允许普通项目图片和受控的 `.nanodesk/uploads/images/` 上传图片；其他内部控制路径仍被拒绝，并校验规范路径及符号链接不能逃逸上传目录。识别仍须通过工具权限、审批和 8MB 输入限制，保存或预览成功不等于识别成功。

## 识别方式选择

在 **设置 → 环境依赖 → OCR** 的下拉菜单中选择识别方式，点击保存生效。旧配置默认使用本地 PaddleOCR。

| 方式 | 配置 | 调用方式 |
| --- | --- | --- |
| 本地 OCR | 本机 PaddleOCR 环境 | 保持现有 CLI 与模型参数 |
| 外部 OCR API | 完整 `/v1/chat/completions` 地址、支持图片输入的模型名、可选 API Key | OpenAI 兼容 JSON，图片以 data URL 发送 |
| MinerU API | 完整自建服务接口地址、可选 API Key | multipart `files` 上传，返回 Markdown |

MinerU 旧版地址示例：`http://127.0.0.1:8000/file_parse`；新版地址示例：`http://127.0.0.1:8000/v1/file_parse`。地址必须包含接口路径，不会自动猜测或回退。请使用文件解析 API，而非底层 VLM 推理服务地址。参见 [MinerU 自建服务文档](https://opendatalab.github.io/MinerU/usage/http_api/)。

两类远程服务均使用可选的 `Authorization: Bearer <API Key>`。API Key 随应用其他设置保存在本机 `settings.json`，未做应用层静态加密。远程方式会把所选项目图片上传至配置的服务，不需要安装本机 PaddleOCR。不同方式的地址与密钥分别保留，切换后需保存。

新版 MinerU 的 `202` 响应会触发有界轮询，最多 60 次，等待阶段最多 320 秒；初次请求超时 320 秒。本地仍使用原有 90 秒超时。服务错误、任务失败、部分失败或空结果不会静默回退本地 OCR。`raw` 返回远程 JSON 或本地 CLI 原始输出。当前仍只接入图片 OCR，未增加 PDF/Office 附件解析。

自动化与手动联调标准见 [OCR 接入测试方案](../05-开发运维/OCR接入测试方案.md)。

## 运行时依赖

可以在环境设置页安装本地 OCR 运行时，也可以手动执行：

```powershell
python -m pip install --user paddleocr paddlepaddle
```

NanoDesk 会检查 `PATH`、当前 Python 的 `sysconfig.get_path("scripts")` 目录，以及 `NANODESK_PADDLEOCR_BIN`。如果仍然找不到可执行文件，可以在启动 NanoDesk 前把 `NANODESK_PADDLEOCR_BIN` 设置为完整的 `paddleocr.exe` 路径。

## 图片附件

用户可以通过聊天输入区的回形针附件按钮添加图片，也可以拖拽或粘贴图片。前端会通过 `save_chat_image_attachment` 把支持的图片保存到附件根目录下的 `.nanodesk/uploads/images/`；保存与预览不经过 Agent 工具的内部目录限制。

附件根目录规则：

- 项目会话：当前项目目录。
- 普通会话：Tauri app data 下的 `temp/` 目录。
- 归档预览：优先使用归档会话的 `project_path`，没有项目路径时使用 `temp/`。

图片消息通过 `renderMessageContent` 进入 `ImageAttachmentMessage`，再调用 `read_chat_image_attachment` 读取 data URL。这样普通聊天、历史消息和 Settings > Archive 预览都使用同一条缩略图和大图打开链路。

## Agent 工具

模型可以这样请求 OCR：

```xml
<tool_call name="ocr_image">
  <path>images/example.png</path>
  <output_format>text</output_format>
</tool_call>
```

参数：

- `path`：必填，根目录内且通过工具策略的相对图片路径；测试示例需预先准备该文件。
- `output_format`：可选，`text` 或 `raw`，默认是 `text`。

后端要求输入文件必须位于当前根目录内，支持 `png`、`jpg`、`jpeg`、`bmp`、`webp`、`tif`、`tiff` 图片。聊天附件最多可保存 25MB，但 OCR 执行阶段限制为 8MB，以保护本机内存。

## 运行时兼容

当进程环境中没有显式定义 `FLAGS_enable_pir_api` 时，NanoDesk 会为 PaddleOCR 子进程设置 `FLAGS_enable_pir_api=0`。这会让 PaddleOCR 使用旧推理路径，绕开部分 Windows/Python 环境在加载 PP-OCRv6 small 模型时出现的 `ConvertPirAttribute2RuntimeAttribute` 错误。

如果需要主动测试 Paddle 的 PIR 路径，可以在启动 NanoDesk 前自行定义 `FLAGS_enable_pir_api`。

OCR 子进程还会使用保守默认值：

- 90 秒超时；超过限制会终止子进程。
- `text_det_limit_side_len=960` 和 `text_det_limit_type=max`。
- 文本识别 batch size 为 `1`。
- CPU 线程数限制为 `2`。
- 默认关闭 MKL-DNN、HPI 和 CINN。

## 模型配置

默认 CLI 调用使用：

- `PP-OCRv6_small_det`
- `PP-OCRv6_small_rec`
- CPU 执行
- 检测模型输入最长边限制为 960px
- 关闭文档方向分类、文档矫正和文本行方向分类

这个默认路径更偏向本地桌面环境的稳定和资源可控。后续可以再增加高精度可选配置。
