# 定时与事件任务

## 使用

在侧栏进入「定时与事件任务」，点击「新建任务」。用一句话描述任务，例如「每天上午九点，生成一份项目日报模板」，选择已配置的聊天模型和工作目录，点击「识别时间和任务」。AI 提取任务名称、执行要求、时间和频率；核对识别结果后点击「保存任务」启用。修改描述或模型后需要重新识别。识别会调用所选模型，执行任务也使用此模型；每次点击识别都会产生独立的模型请求，其费用和耗时不计入后续任务预算。

自然语言创建支持单次、固定间隔和每日定时。识别请求提供点击识别时的当前时间和本机 UTC 偏移，「半小时后」以该时刻为基准；固定间隔则从保存时起等待首个间隔。每日任务保存识别时的 UTC 偏移，不随本机时区或夏令时自动变化。提示词要求模型对时间不明确、缺少任务内容或每周、工作日、每月、多时间点、时区转换、带起止日期的重复任务等无法表示的规则返回补充信息或限制说明。应用会校验模型返回的必填字段、触发类型、数值范围及单次时间是否仍在未来，但不会独立判断原文语义与配置是否一致；必须人工核对，不能将模型澄清视为确定性保障。

此入口仅创建 AI 文本任务，上下文文件列表为空，不会读取或检索工作目录中的文件，也不继承当前聊天的消息和附件。工作目录用于保存成果；新建任务不提供上下文文件配置；编辑已有 AI 任务会保留原有上下文文件、重试策略、启用状态和独立预算。自然语言创建默认启用、不自动重试，错过任务时合并补执行一次，使用全局默认预算。

新建和编辑统一使用 AI 描述，已移除手动配置表单。编辑已有 AI 定时任务时带入任务名称、时间规则和执行要求；修改后重新识别、核对并保存，保留任务 ID 与其他执行策略。当前不新增脚本或文件监听配置能力；已有脚本、文件监听任务继续运行，支持暂停、立即执行、删除和记录查看，编辑时显示暂不支持提示，不会隐式转换为文本任务。AI 配置不支持每周、工作日或每月调度。

AI 定时任务支持通过描述编辑，所有任务支持暂停、删除、立即执行，以及查看最近 100 条执行记录。暂停会取消尚未开始的入队和延迟重试；正在执行的任务允许结束，暂停后不再自动重试。删除会删除配置和记录，保留已经生成的成果文件；执行中不能删除。

### 后台执行能力与旧任务兼容

- **AI 办公任务**：选择已有聊天模型，填写提示词，可指定目录内的 UTF-8 文本相对路径，每行一个。每个文件最多 64KB、最多 20 个，整个输入最多 256KB。读取仍经过项目路径安全策略；结果保存为 `.nanodesk/automation/<执行ID>-<尝试次数>.md`，同时显示在执行详情中。模型调用最长 180 秒。第一版生成文本成果，不执行聊天 Agent 工具循环，不自动读取变化文件，不抽取 PDF/Word/Excel；需要处理这些文件时可配置脚本。
- **本地脚本命令**：保存时明确确认后台执行授权；执行时仍经过现有命令安全策略，在指定工作目录运行，最长 45 秒。输出和错误写入执行记录。配置自动重试时，脚本应能够安全重复执行；默认重试次数为 0。

任务可在聊天页面之外执行，不依赖当前选中的会话，也不把预设提示词作为用户画像样本。

## 触发规则

| 类型 | 行为 |
| --- | --- |
| 单次 | AI 按本机时区识别未来时间，保存为 UTC 时间戳；自动触发后清除下次时间 |
| 固定间隔 | 保存后等待指定秒数；后续沿原定时间序列推进，最短 10 秒 |
| 每日 | 使用保存的小时、分钟和 UTC 偏移，默认取创建时本机偏移；旅行或夏令时变化时需要通过描述重新识别时间规则 |
| 文件变化 | 每 2 秒扫描目录中的新增、修改、删除，通过文件大小和修改时间判断变化；可选择递归子目录，稳定达到防抖时间后合并触发一次 |

文件监听首次保存时建立基线，已有文件不会触发任务。忽略 `.git`、`.codegraph`、`.nanodesk`、`node_modules`、`target` 目录及符号链接，避免成果写入引发循环；最大 20000 个文件。扫描失败不把无法访问的目录当成全部文件被删除，而是在任务卡显示错误；恢复访问后继续对比。两次扫描之间出现又消失的短暂变化，以及大小和修改时间都未改变的内容修改，可能无法捕获。

同一任务同时最多存在一条未处理记录，防抖期间路径会合并；执行期间新变化保留，结束后再触发。不同任务进入同一队列，第一版串行执行，触发扫描独立于执行 worker。

## 重试与补执行

- **失败后延迟重试**：最多 0–10 次额外重试，每次等待指定秒数（5–86400 秒）。等待时间、已尝试次数和错误持久化，重启后继续等待或执行已经到期的重试。
- **合并补执行一次**：定时任务错过多个时间点时合并入队一次，再将游标推进到未来；文件任务保留快照，下次启动或重新启用后对比离线期间变化，合并触发一次。
- **跳过**：跳过超过调度宽限时间的定时触发，继续等待未来时间；文件任务启动和重新启用时重建基线，忽略停用期间变化。正常轮询允许 5 秒调度宽限。
- **结果未知**：应用重启时，原来的执行中记录标为结果未知。脚本超时也标为结果未知，不自动重试。同一任务会暂停继续触发，直到用户检查实际结果，选择「重新执行」或「忽略」。重新执行需要确认，失败记录也允许手动重新执行。

应用运行或驻留系统托盘时调度；完全退出和电脑休眠期间不执行。再次运行或唤醒后按以上规则处理。不会安装系统计划任务，也不会在退出后启动应用。

## 实现与数据

- 后端：`src-tauri/src/agents/automation/mod.rs`；触发扫描 worker 与执行 worker 分离。
- 前端：`src/components/AutomationPanel.tsx`，作为主视图插件注册；`src/components/automation/NaturalAutomationCreator.tsx` 提供自然语言创建入口，`src/lib/automationLanguage.ts` 调用模型并校验返回配置，`src/hooks/useAutomationController.ts` 保存任务。
- IPC：`list_automations`、`save_automation`、`set_automation_enabled`、`delete_automation`、`list_automation_runs`、`run_automation_now`、`recover_automation_run`。
- 自然语言识别复用 `chat` IPC，提交任务描述和时间信息，要求模型返回 JSON，输出上限设为 1200 Token；识别阶段不创建调度任务，保存时才调用 `save_automation`。
- 数据库：app data 下的 `nanodesk-automation.sqlite3`，SQLite WAL。
- 触发游标与新执行记录在同一事务提交；领取任务也在事务中修改状态。执行记录保留当时配置，重试使用该配置，不因后续编辑改变。
- 配置存在未处理记录时不能编辑；可先暂停取消待执行记录，或处理失败/结果未知记录。
- 执行结果通过 `automation-changed` 事件更新当前任务界面，并记录操作日志；成功结果持久化后按任务预算配置发送系统完成通知，不发送外部消息。

## 任务预算与完成通知

任务可使用全局默认预算或配置独立预算，覆盖估算费用、执行时间和步数。每次触发独立计量，同一记录的重试和恢复不重置已用量；超限进入 `budget_paused`，不自动重试或重复触发。可在详情中调整预算，再重新执行或忽略。成功结果持久化后发送系统通知，可关闭。详见[任务预算与通知](任务预算与通知.md)。

## 验证

Rust 测试覆盖单次/每日/间隔调度、补执行合并与跳过、防重复领取、防抖、文件新增修改删除及输出排除、重试延迟与次数上限、重启后的快照与重试恢复、未知结果人工处理、暂停语义，以及真实本地命令执行与结果存储。另使用本地模拟 OpenAI 兼容服务验证 AI 上下文读取、请求与 Markdown 成果保存。前端测试验证时间解析和时区显示。浏览器交互检查使用模拟 Tauri IPC，验证表单提交与执行详情；不作为用户实际模型服务或桌面端联调证明。

自然语言创建测试使用模拟模型响应，验证配置提取和数值校验、展示模型返回的澄清信息、拒绝无效响应、修改描述后丢弃旧结果、过期时间拦截及传给保存回调的配置。组件测试使用模拟 React 状态和保存回调，不是浏览器或真实 IPC 端到端测试；不证明实际模型能准确识别时间、频率或所有歧义。
