# 聊天 Token 统计

主聊天与文档聊天在消息下方展示 Token 统计。估算数字统一使用 `~`；服务端返回的用量不加 `~`。

## 展示与范围

| 阶段 | 示例 | 含义 |
| --- | --- | --- |
| 用户发送后 | `问题 ~128 tokens` | 仅本次输入文字，不含历史、系统提示、文档正文和自动追加的图片提示 |
| 等待输出 | `等待响应…` | 尚未收到正文或可见思考 |
| 流式输出 | `已生成 ~256 tokens · ~32.5 tokens/s` | 已收到的模型文本估算量，以及最近 2 秒速度 |
| 完成且返回用量 | `输出 512 tokens · 平均 ~34.1 tokens/s` | 服务端输出量与文本估算平均速度 |
| 完成但未返回用量 | `输出 ~512 tokens · 平均 ~34.1 tokens/s` | 保留文本估算 |
| 停止或失败 | `已停止 · 已生成 ~256 tokens` / `失败 · 已生成 ~256 tokens` | 保存部分输出及状态，同时展示可计算的平均速度 |

鼠标悬停助手统计行，可查看调用时的模型、服务端请求输入 Token、输出来源及速度口径。服务端请求输入量与“问题 Token”不同：前者按服务端口径涵盖实际发送的历史、系统提示、检索或附件上下文；字段缺失显示未知，服务端返回的 0 保留为 0。隐藏推理可能包含在服务端输出用量中。

历史消息缺少统计元数据时不补造统计；功能启用后产生的统计随消息保存，重开会话后恢复。暂停、临时任务和重新生成沿用原有行为；临时问题同样保存输入文字估算。

## 计算规则

- 文本估算沿用现有用量页面的轻量规则：`ceil(ASCII 字符数 / 4) + 非 ASCII Unicode 字符数`。不是模型 tokenizer，不作为计费依据。
- 输出计数分别累计正文流和可见思考流的字符数后估算，再相加；包括模型输出中的工具参数及结构化文本。不会把一个流式分块算成一个 Token，也不会对每个分块单独向上取整。
- 后台约每 500ms 刷新统计，正常文本更新也会携带最新统计；没有新分块时仍刷新速度，空闲超过 2 秒后降为 0。
- 实时速度为最近 2 秒内新增估算 Token / 窗口秒数；刚开始不足 2 秒时使用从首个输出到当前的时间。首个分块时尚无有效时间跨度，显示 `—`。
- 平均速度为累计估算输出 / 累计生成秒数；生成时间取每段请求的首个到最后一个输出分块，排除首字等待、自动续写请求间等待和末尾用量事件等待。只有单个分块等无法形成时间跨度的情况显示 `—`。
- 服务端用量只用于最终 Token 数，不替换速度分子，避免隐藏推理导致速度口径变化。
- 一次工具步骤或助手响应单独保存统计；自动续写的多个请求合并到同一逻辑响应中。每个请求内的累计用量取最新值，再跨请求相加；任一请求缺少某字段时，整条响应的该字段保持未知。

## 协议、保存与兼容

OpenAI 兼容流请求携带 `stream_options.include_usage=true`，读取包括 `choices: []` 在内的用量事件，并继续等到流结束。若服务端以 400/422 明确拒绝这个选项，只重试一次不含此选项的请求。网络、鉴权和服务端异常不会因此自动重发。

Anthropic 兼容流读取 `message_start.message.usage` 和后续 `usage`，分别保留已知的输入、输出累计值。接口没有返回用量时，聊天仍使用估算。

统计由 Rust 后台执行器持有，切换会话或卸载页面不会重置。`MessageMetadata.question_tokens` 保存输入文字估算，`MessageMetadata.token_statistics` 保存输出估算、服务端输入/输出量、生成时间、速度、模型标识和完成/停止/失败状态。使用现有 `metadata_json`，无需数据库表迁移。旧消息及内部消息兼容缺失字段。

系统设置中的“用量分析”和任务预算沿用各自原有统计口径，本功能不修改它们，也不新增费用面板。

## 验证

- 前端测试：Unicode 与中英文估算、`~` 展示、实际 0 与缺失用量、状态文案、共享消息组件、附件文字与临时任务输入边界。
- Rust 测试：分块不变性、滚动速度空闲归零、平均时间排除等待、OpenAI/Anthropic 用量解析、尾部用量与重复事件、自动续写汇总、兼容选项降级、失败/停止保存、跨会话模型隔离、重新生成和 SQLite 重开恢复。
- `npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml --lib`。

协议和执行器验证使用本地模拟模型服务；不代表已对所有用户配置的真实模型服务完成联调。
