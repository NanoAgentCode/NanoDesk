# 长期目标任务

长期目标把多次触发连接成同一个持续任务。每次执行推进一个阶段，保存累计进度、下一步与成果依据；后续触发结合历史消息和检查点继续推进，模型判断全部完成条件满足后停止调度。

## 创建与使用

在「定时任务」点击「新建长期目标」，填写名称、目标、完成条件、聊天模型和工作目录。目标应描述想得到的结果，完成条件应便于检查，例如“将指定目录中的资料整理成索引，每一项附来源路径，逐项读取核对”。场景不受此示例限制。

触发方式支持固定间隔、每日时间和文件变化。每日时间使用保存时的 UTC 偏移。文件变化首次建立基线，不将已有文件视为新增；默认递归监听，支持防抖。保存后等待触发，也可以点击「立即执行」。

任务卡显示累计进度、下一步、成果依据和阶段数。每个阶段的输出保留在执行记录，工具执行和模型消息保留在独立的「长期目标 · 名称」会话中。自动任务输入不作为用户画像样本。

## 推进、暂停与完成

- **持续推进**：每次触发只要求推进一个阶段。模型仍可在本阶段进行多轮文件读写，受现有任务预算限制。
- **暂停**：关闭任务开关取消待执行记录；执行中的目标会在检查点接收暂停信号。已经开始的文件操作先记录结果，暂停不会回滚操作。
- **阻塞**：缺少必要信息、需要不支持的操作、阶段执行出错或连续三次返回相同进度和下一步时，停止自动推进。检查目标会话和成果，编辑目标补充要求或自行处理阻塞后，重新打开开关。恢复保留历史进度。
- **完成**：检查点必须包含完成依据，任务停用并清除下次时间。完成目标不可重新启用或编辑；后续工作创建新目标。中间阶段结束不发送系统完成通知，整体完成才通知。

运行范围仅限应用运行或驻留托盘期间，不安装系统服务或系统计划任务。重启保留目标、历史进度和触发游标。若退出时某阶段仍在执行，沿用自动任务的“结果未知”处理：检查实际成果，再选择重新执行或忽略，不自动重放可能产生过副作用的操作。

## 执行边界

目标阶段复用后台 Agent 的模型上下文、工具循环与预算，当前开放项目内 `read_file` 和 `write_file`，写入沿用现有自动模式策略：Markdown、文本和 `docs/` 内文件可以自动写入，其他路径的写入会阻塞并要求人工处理。执行层校验工具名称和路径，不执行命令、MCP 或其他外部操作；需要这些操作时显示阻塞原因。文件读写不会自动提取 PDF、Word、Excel。工作目录不应选为不希望助手修改的资料目录。

各次触发独立使用现有任务预算，同一条执行记录的恢复沿用已消耗量。长期目标不自动重试；发生预算暂停时，在执行详情调整预算后恢复。阶段预算不是整个长期目标的累计费用上限。

完成判断由所选模型根据完成条件和实际工具结果做出；检查点格式校验会拒绝没有完成依据的结果，但不能独立证明依据真实或覆盖所有条件。重要成果应人工复核。没有有效检查点时保留上次进度并停用任务，防止丢失进度后继续循环。

已有执行进度的目标不能变更工作目录或转换为普通任务。编辑目标、完成条件和触发规则会保留进度，不会重新创建成果。

## 实现与验证

复用 `nanodesk-automation.sqlite3` 的自动任务与队列表，新增 action 类型 `goal`，旧任务通过可选进度字段保持兼容。进度与阶段执行结果在同一事务提交；触发游标、排队、领取和跨进程 worker 租约沿用现有机制。目标阶段不会注册可由聊天恢复器自动重启的执行请求。

Rust 测试覆盖检查点校验、进度重启恢复、完成后停止、阻塞恢复、连续无进展停止、无效输出不覆盖进度，以及本地模拟模型服务驱动的真实文件写入、后续阶段读取和历史检查点传递。模拟服务验证执行链路，不证明用户实际模型能正确分阶段或判断完成条件。

前端测试覆盖目标必填项、触发配置和保存的数据。可运行 `npm.cmd test`、`npm.cmd run build`，以及 `src-tauri` 下的 `cargo test --lib`。
