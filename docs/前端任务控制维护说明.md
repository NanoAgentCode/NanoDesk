# 前端任务控制维护说明

任务规划面板按职责分层：

- `src/api/taskControl.ts`：暂停、临时任务、父子任务查询与返回主线的类型化 IPC。通用任务列表和决策仍使用 `api/agents.ts`。
- `src/lib/serialPoller.ts`：串行轮询、刷新合并、旧结果丢弃、失败退避与销毁。
- `src/hooks/useTaskSummary.ts`：会话级快照、操作提交锁、错误状态及生命周期。
- `src/components/TaskSummaryPanel.tsx`：布局、输入与导航意图，不直接调用 IPC。

## 异步约定

1. 列表与父子关联查询全部成功后才发布快照；失败保留最后成功结果，单独显示读取错误。
2. 同一轮询器同时只执行一个请求。刷新会使在途结果失效，多次刷新合并为下一次请求。
3. 读取失败按 2、4、8 秒等间隔退避，最多 30 秒；成功恢复 1 秒间隔。手动刷新立即请求，页面隐藏时跳过定时读取，重新显示时刷新。
4. 提交使用同步引用锁，避免 React 更新按钮禁用状态之前的重复点击。请求完成前不能再次提交该会话当前操作。
5. 会话切换或组件销毁后，旧操作不再修改界面或触发成功导航。旧请求本身不会被取消：后台操作可能已生效，回到原会话后以持久化结果为准。
6. 读取错误和操作错误分开保存。普通轮询成功不会清除操作失败；重新操作或切换会话才重置操作错误。

后端仍拥有任务执行权、权限校验和副作用记录。前端刷新、隐藏窗口或卸载面板不应停止后台任务。

## 回归入口

- `npm.cmd test`：包含轮询重叠、过期结果、销毁、退避、隐藏页面，以及现有任务分流和 IPC 合同测试。
- `npx.cmd tsc --noEmit`：类型检查。
- 浏览器验收：快速连点；操作未返回时切换聊天；新聊天提交操作后旧请求返回；读取刷新后仍显示操作错误；暂停、插入临时任务、返回主线。
