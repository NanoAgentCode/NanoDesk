# 模块化重构记录

本次按后端、前端、跨层契约三个阶段重构现有工程。目标是把职责混杂的大文件拆成可定位、可测试的模块，保留现有功能、界面、IPC 名称和数据格式，不增加新的运行时依赖。

## 1. 后端边界

| 入口 / 模块 | 重构后的职责 |
| --- | --- |
| `lib.rs` | 模块装配、启动、IPC 注册、桌面和 CLI 入口 |
| `app_state.rs` | 共享应用状态及底层流式取消注册表 |
| `commands/` | 按条目、模型、会话、MCP、文件、环境、观测等能力分组的 Tauri 适配器 |
| `services/` | 工具执行、OCR、环境依赖及观测服务，供 IPC 和后台调用 |
| `desktop.rs` | 原生窗口、托盘、自启动与退出 |
| `background_agent.rs` / `background_agent/` | 兼容入口；协议、所有权、范围校验、用户决定、生命周期、执行循环和上下文准备各自独立 |
| `automation.rs` / `automation/` | 兼容入口；类型、存储、调度规则、文件扫描、验证、IPC、动作执行和 worker 分开 |
| `llm.rs` / `llm/` | 保留聊天入口；区分 OpenAI/Anthropic、请求参数、模型发现、Embeddings 和 SSE 传输 |
| `runtime.rs` / `runtime/` | 保留存储接口；区分连接、Schema、恢复、run、tool、时间线及执行请求存储 |
| `db/schema.rs` | 原有 Schema 初始化与列迁移；条目/记忆读写辅助方法归属对应 repository |
| `cli.rs` / `cli/` | CLI 会话编排保留在入口，模型配置、上下文、终端主题和输出展示独立 |

后台模块的内部辅助接口限制在本模块内，不扩大到外部插件。存储家族仍共享同一 SQLite connection 和模型定义，不另加 repository 框架，也不改动 SQL 和持久化字段。

调用方向以入口到能力模块为主：IPC 适配器调用服务或存储；后台生命周期启动执行器；执行器调用范围/决策/上下文模块与已有服务。原 `crate::AppState` 等共享入口通过有限重导出保持兼容。

## 2. 前端边界

- `api.ts` 保留兼容聚合出口；`api/` 按能力提供类型化函数，143 个既有运行时导出保持兼容。新模块可直接引用对应能力文件。
- `hooks/chat/types.ts` 单独维护聊天组合接口；`useChat.ts` 继续负责编排发送、附件和用户动作。
- `useBackgroundAgents` 只维护后台事件投影、刷新版本与启动请求；卸载仅注销订阅，不取消后台任务。
- `useChatHistory` 负责按会话恢复消息、推理、工具与运行记录，异步结果继续校验请求序号和当前会话。
- `useAutomationController` 负责自动任务的数据加载、保存、审批确认和错误状态；`AutomationPanel` 保留列表选择和详情展示；`AutomationEditor` 是受控表单。
- `useAppCloseBehavior` 管理窗口关闭事件和保存的关闭偏好；项目、重命名与关闭弹窗分到 `components/app/`，保留原文案与事件行为。

“易交互”在本次重构中落实为模块接口明确、受控状态和事件责任清晰。界面布局、操作顺序、审批方式和可见功能保持原样。

既有 `db/*_store`、`hooks/useModel/useMcp/useProjects`、`components/settings`、`lib` 工具函数及插件注册表已有独立职责，继续沿用。没有为了统一文件大小重写这些模块。

## 3. 兼容与验证

- IPC 契约测试记录并检查原有 142 个 command 名称及注册唯一性；内部注册路径可改变，外部 command 名称保持不变。
- 前端 API 导出契约检查全部既有运行时导出；原 `../api` 和 `../types` 导入仍有效。
- 保留全部原有 Rust 与前端测试，验证数据库初始化、运行时恢复、工具审批、模型协议、CLI、上下文与后台执行。
- 浏览器检查实际 React Hook 与表单组件，使用模拟 Tauri IPC 覆盖会话切换、并发提交、后台续跑、任务编辑/暂停、成果展示及关闭偏好。
- 本次不验证用户的真实模型服务、WebView 麦克风、OCR 环境或 SSH 服务器；这些需要对应环境联调。

```powershell

npm.cmd run build
cd src-tauri
cargo test --lib
cargo check
```

重构前后的业务行为是完成标准；模块数量和文件行数只用于定位职责，不作为功能正确性的证明。

## 4. 执行内核职责收敛

公共能力执行集中在 `services/execution.rs`：工具参数与插件校验、当前安全策略校验，以及文件、命令、OCR、MCP 的具体分派。`services/agent_tools.rs` 只负责工具调用的启动、150 秒超时、审计与成功/失败状态记录。普通聊天通过该生命周期服务进入能力执行；自动任务的命令动作直接调用公共命令入口，复用策略与进程执行，并保留原有原始输出。

明确边界：

- 聊天执行器继续持有会话、模型循环、审批等待、澄清、取消、续写和恢复。
- 自动任务继续持有触发、重试、任务预算、AI 上下文和成果文件；不转成聊天 Agent，不新增工具调用记录。
- 公共能力服务不决定审批、不持有任务状态、不添加预算或恢复机制；已开始的工具仍先记录结果，再响应聊天停止请求。
- 模型调用继续复用 `llm`；AI 自动任务与聊天的不同超时、提示词和输出协议保持现状。

本次仅调整内部职责与调用路径，IPC、数据库、前端、工具输出和策略限制保持兼容。验证使用公共命令入口的禁用策略与原始输出测试，并运行现有 Rust 工具策略、后台聊天、自动任务和 IPC 契约回归测试。
