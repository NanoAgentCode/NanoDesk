# 架构与模块设计

## 1. 前端分层

前端入口是 `src/App.tsx`。它是微内核的组合根，只组合全局状态、应用壳和插件注册表；主视图与设置页由 `src/plugins/builtin.tsx` 注册，具体业务逻辑主要下沉到 hooks：

UI 基础组件使用 Mantine 8，统一主题配置位于 `src/theme.ts`。`App.tsx` 通过 `MantineProvider` 把现有深色、浅色和跟随系统模式同步给组件库；业务 hooks 与 Tauri command 边界不因组件库迁移而改变。组件级 CSS 继续负责聊天消息、终端和工作区等产品特有布局，通用按钮、输入、选择、弹窗、导航、通知和状态控件优先使用 Mantine。

- `useChat`：发送消息、流式事件、上下文压缩、RAG 召回、Agent run、工具执行续写、图片附件上传。
- `useConversations`：普通会话、项目会话、归档会话、会话模型绑定和预览消息加载。
- `useModel`：模型配置、连接测试、当前模型、embedding 配置。
- `useProjects`：项目列表、项目目录创建、项目会话映射、打开/切换项目时的轻量文件索引缓存，以及项目级代码/文档索引触发和统计。
- `useRagFiles`：RAG 文件列表、索引状态、召回。
- `useMcp`：MCP server 配置、连接、断开、工具刷新。
- `useSkills`：Skills 同步、本地 Skills、启用状态和 app data 下的 `temp/` 目录。
- `useWorkspace` / `useMemory`：本地条目和长期记忆管理。
- `useObservability`：观测 span 拉取、trace 分组、时间线展开状态。

`src/api.ts` 是前端统一后端调用封装。组件不直接写 `invoke`，而是调用这里的类型化函数，保持 command 名称、参数和返回类型集中管理。

## 2. UI 模块

主要界面分为：

- `ChatPane`：聊天消息、模型选择、RAG 文件条、图片附件入口、运行时面板。
- `MarkdownMessage`：聊天 GFM Markdown 与 KaTeX 数学公式渲染、外部链接弹出、项目文件链接打开，以及基于当前项目文件索引的路径/裸文件名自动链接化。
- `Sidebar`：普通会话、项目入口、项目会话，以及插件主视图入口渲染。
- `WorkspaceGrid`：笔记、提示词、记忆等本地对象管理。
- `SettingsModal`：设置插件宿主，负责导航与当前插件页渲染，不硬编码具体设置页。
- `SettingsArchiveTab`：归档列表和归档消息预览。图片消息通过 `renderMessageContent` 和 `ImageAttachmentMessage` 渲染，附件根目录来自归档会话的 `project_path`，没有项目路径时回退到 `skills.tempDir`。
- `SettingsMemoryTab` / `SettingsProfileTab`：前者只管理普通手工记忆，后者独立管理异步画像配置、处理状态、调用预算、事实删除与清空。
- `OpsPanel`：SSH 服务器配置、连接测试、上传文件、交互式终端。

## 3. 后端分层

Rust 后端由 `src-tauri/src/lib.rs` 装配：

- 初始化 Tauri plugin、系统托盘和 app data 目录，并在 `logs/` 启动按天滚动的系统日志。
- 打开主业务库、Agent 运行时库、观测库。
- 创建 `AppState`，包含 `Database`、`RuntimeStore`、`ObservabilityPipeline`、`McpClientManager`、`PluginRegistry` 和 Ops SSH session 状态。
- 注册所有 Tauri command。

后端模块边界：

| 模块 | 职责 |
| --- | --- |
| `db.rs` | 主业务库连接、schema 初始化、轻量迁移、共享 row mapper 与数据库入口 |
| `db/item_store.rs`、`db/config_store.rs`、`db/conversation_store.rs` | 条目；模型/MCP/Ops 配置；会话和消息读写，其中用户消息与画像观察在同一事务写入 |
| `db/rag_store.rs`、`db/memory_store.rs` | 会话级 RAG 存储；长期记忆 CRUD、FTS、sqlite-vec 和图谱存储 |
| `db/code_index_store.rs`、`db/project_index_store.rs` | 代码索引与通用项目文档索引的替换、统计和查询 |
| `memory.rs` | 长期记忆 embedding 编排、懒迁移和关系库/向量/图谱混合召回 |
| `profile.rs`、`db/profile_store.rs` | 用户画像候选过滤、异步批处理、跨进程租约、调用预算、Reducer、删除屏障和上下文注入 |
| `code_index.rs` | 项目代码文件扫描、实体/关系/片段抽取和代码索引查询 |
| `project_index.rs` | 项目普通文档扫描、片段切分和通用项目文档索引查询 |
| `runtime.rs` | Agent run、step、tool_call 持久化 |
| `observability.rs` | span 数据结构、sink trait、SQLite sink |
| `logging.rs` | 系统操作日志、按日文件 sink 和 7 天自动清理 |
| `llm.rs` | 模型请求、流式事件解析、embedding |
| `mcp.rs` | MCP 连接、工具列表、工具调用 |
| `core/plugin.rs` | 后端插件契约、插件清单、Agent 工具扩展点和注册冲突校验 |
| `plugins.rs` | 内置 Core Agent Tools 与 MCP Tool Adapter 插件装配 |
| `agent_runner.rs` | XML tool_call 解析和运行时结果模型；工具识别与参数校验委托给插件注册表 |
| `tool_policy.rs` | 工具路径、命令、MCP scope、风险分级和审批策略 |
| `ops.rs` | Ops server command、SSH/SFTP、交互式 session 和 Ops AI 调用 |
| `skills.rs` | GitHub Skills 同步和本地 Skills 列表 |
| `cli.rs` | `nano` 参数、首次模型配置、项目索引、会话恢复和终端交互 |
| `models.rs` | 前后端共享的序列化模型 |
| `error.rs` | 统一错误类型 |

## 4. 微内核与插件契约

应用采用“稳定内核 + 静态插件”的第一阶段实现。插件随应用编译发布，不在运行时加载不可信动态库；这样先获得清晰扩展边界，同时保留 Tauri 权限模型和 Rust 类型检查。

前端内核位于 `src/core/plugins.tsx`：

- `AppPluginRegistry` 是唯一注册入口，启动时拒绝重复的插件、主视图或设置页 ID。
- `MainViewContribution` 允许插件贡献侧栏入口和惰性加载的主视图组件。
- `SettingsContribution` 允许插件贡献设置导航、激活钩子和设置内容。
- `src/plugins/builtin.tsx` 当前注册 Core UI、Skills、MCP、Environment 和 Server Operations 插件。Core UI 贡献通用、记忆库、用户画像、LLM、Embedding、归档和链路追踪设置页；新增同类 UI 能力只需新增插件贡献，不再修改 `Sidebar` 或 `SettingsModal` 的条件分支。

后端内核位于 `src-tauri/src/core/plugin.rs`：

- `AppPlugin` 提供 manifest、Agent 工具定义、工具归属判断和参数校验扩展点。
- `PluginRegistry` 统一暴露插件清单和工具定义，并在启动时拒绝重复插件 ID、重复工具名和声明/归属不一致。
- `CoreAgentToolsPlugin` 提供文件读取、文件写入、命令执行和 OCR；`McpToolsPlugin` 接管 `mcp__` 命名空间。
- Agent Runner 仍负责 tool call 生命周期；插件只扩展工具定义与校验，最终执行仍必须经过 `tool_policy`、用户审批和内核能力调度，插件不能绕过安全边界。

`list_plugins` command 用于查询后端实际加载的插件清单。当前插件注册是显式、静态和进程内的；动态安装、版本解析、启停与隔离执行属于后续阶段，未包含在当前安全边界内。

## 5. Command 设计

Tauri command 按领域分组：

- 本地条目：`list_items`、`search_items`、`create_item`、`update_item`、`delete_item`
- 模型配置：`list_model_configs`、`save_model_config`、`list_available_models`、`test_llm_connectivity`。其中 `list_available_models` 按协议请求 OpenAI 兼容的 `{base_url}/models` 或 Anthropic 兼容的 `{base_url}/v1/models`，前端将结果用于可搜索选择，同时保留模型标识手动输入。
- MCP：`list_mcp_servers`、`connect_mcp_server`、`call_mcp_tool`
- 对话：`list_conversations`、`append_message`、`archive_conversation`
- RAG：`index_rag_file`、`search_rag_context`
- 项目索引：`index_project_code`、`search_code_index`、`index_project_documents`、`search_project_index`
- 手工记忆：`list_memories`、`search_memories`、`create_memory`、`update_memory`、`delete_memory`、`list_relevant_memories`；相关记忆由 FTS/关键词、sqlite-vec KNN、知识图谱一跳扩展三路 RRF 融合
- 用户画像：`get_profile_settings`、`save_profile_settings`、`get_user_profile`、`get_profile_context`、`get_profile_processing_status`、`delete_profile_fact`、`clear_user_profile`、`retry_profile_failures`、`run_profile_worker_now`；画像只从持久化用户消息异步批量生成，与普通记忆独立存储
- Skills：`sync_anthropic_skills`、`list_local_skills`
- 模型调用：`chat`、`chat_stream`
- Agent 运行时：`create_agent_run`、`record_agent_step`、`execute_agent_tool_call`
- 插件内核：`list_plugins`、`list_agent_tool_definitions`
- 项目文件与附件：`list_project_files`、`read_project_file`、`write_project_file`、`open_project_file_location`、`save_chat_image_attachment`、`read_chat_image_attachment`
- Ops：`list_ops_servers`、`save_ops_server`、`test_ops_ssh_connection`、`upload_ops_file`、`start_ops_ssh_session`
- 观测：`list_observability_spans`、`clear_observability_spans`
- 系统偏好与窗口：`get_autostart`、`set_autostart`、`minimize_to_tray`、`show_app_window`、`quit_app`

### 5.1 CLI 复用边界

`src-tauri/src/bin/nano.rs` 通过库入口 `run_cli` 进入 `cli.rs`。CLI 不经过 React、WebView、`src/api.ts` 或 Tauri command，而是直接复用 `Database`、代码/文档索引和 `llm.rs`：

- 项目模式使用与桌面端相同的 app data 和 `conversations/messages`，支持索引更新、会话列表和恢复。
- 临时模式不绑定项目，不扫描项目，也不写入会话历史。
- CLI 目前没有接入桌面端的 Agent runtime、工具审批、MCP、Skills、RAG 附件或 Ops，也不打开 runtime/观测数据库或初始化桌面端按日日志；共享主业务库和 LLM 实现不等于功能完全对等。

## 6. 状态与并发模型

`AppState` 中的 Rust 状态使用 `tokio::sync::Mutex` 包装：

- `db`：主业务 SQLite connection。
- `runtime`：运行时 SQLite connection。
- `observability`：观测 pipeline。
- `mcp`：MCP client manager，持有活动 session。
- `plugins`：启动后只读的插件注册表，不需要锁。
- `ops_ssh_sessions`：交互式 SSH session 句柄。

这种设计简单可靠，适合桌面单用户应用。代价是同一类资源的并发访问会串行化，但能降低 SQLite connection、外部进程和 SSH session 状态复杂度。

画像 Worker 还要处理桌面端、CLI 和多进程同时访问同一主库的情况，因此不能只依赖进程内 `Mutex`。观察预处理、模型批次和前台聊天分别使用数据库租约；`lease_epoch`、`profile_generation`、单调 revision、tombstone 与提交账本共同保证接管、重试和删除后的幂等性。

## 7. 前后端事件

模型流式输出不通过 command 返回完整字符串，而是：

1. 前端生成 `request_id`。
2. 调用 `chat_stream`。
3. Rust 后端通过 Tauri event `chat-stream` 发送事件。
4. 前端用 `listen<ChatStreamEvent>` 过滤当前 `request_id`。

事件类型包括：

- `delta`：普通内容增量。
- `reasoning_delta`：reasoning/thinking 增量。
- `error`：流式请求错误。
- `done`：流式结束。

Ops 交互式 SSH 使用 `ops-ssh` 事件返回 `ready`、`data`、`error` 和 `closed`。

## 8. 依赖方向

推荐依赖方向：

```text
app shell -> plugin registry -> plugin contributions -> hooks -> api -> tauri commands
tauri commands -> plugin registry / policy -> backend capabilities
```

跨层标识必须显式传递。尤其是 `project_path`、`conversation_id`、`model_config_id`、`trace_id`、`tool_call_id` 和图片附件根目录，不应该通过显示名或隐式全局状态猜测。

## 9. 项目文件索引与消息链接

项目文件索引是前端内存状态，不是后端持久索引：

1. `useProjects` 在打开、创建、选择或恢复活动项目时调用 `listProjectFiles(project.path)`。
2. 返回的 `ProjectFileEntry[]` 按项目真实路径缓存在 `projectFilesByPath` 中，并通过 `getProjectFilesForPath` 暴露给聊天层。
3. `useChat` 根据当前会话绑定的项目路径取文件列表，传给 `ChatPane`、`ImageAttachmentMessage` 和 `MarkdownMessage`。
4. `MarkdownMessage` 基于文件列表构建文件名索引，让 `MarkdownMessage.tsx` 这类裸文件名可以解析到 `src/components/MarkdownMessage.tsx`。
5. 对于已包含目录的相对路径，渲染层保持原路径；对于同名裸文件名，当前策略优先目录更浅、路径更短的文件。
6. 点击项目文件链接时前端只传 `projectPath + relativePath` 给 `open_project_file_location`，最终越界校验和文件存在性判断仍在后端完成。

同一个渲染组件还通过 `remark-math` 识别 `$...$` / `$$...$$`，再由 `rehype-katex` 生成公式节点。项目路径自动链接插件与数学插件并列工作，行内代码和代码块继续排除在路径自动链接之外。
