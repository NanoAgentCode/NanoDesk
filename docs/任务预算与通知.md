# 任务预算与通知

## 配置入口

- 通用设置 → 任务预算与通知：设置新任务默认成本、执行时间、步数和完成通知；选择模型并填写输入 / 输出单价，统一单位为人民币元 / 百万 Token。免费模型可明确填 0，未配置单价不会显示为免费。
- 聊天顶部 → 任务预算：覆盖此会话之后启动的任务，或恢复使用全局默认值。已有任务的预算不随默认设置变化。
- 定时与事件任务编辑器 → 单独配置此任务预算：覆盖默认值。每次触发产生独立预算记录，同一记录的重试继续累计。
- 聊天的 Agent Runtime、定时任务的详情 / 成果：展示该任务已用费用、时间、步数。暂停或失败后可保存调整后的上限，再通过原恢复 / 重新执行按钮继续。

默认不限制费用，执行时间 900 秒、64 步，成功完成通知开启。时间允许 1–604800 秒，步数允许 1–10000；费用留空表示不限制，填写时必须为正数。旧配置自动使用兼容默认值。

## 费用与步数

费用只覆盖任务所选聊天模型及长历史压缩调用，不包括嵌入检索、外部工具服务、脚本中自行调用的付费接口。输入按 UTF-8 字节数及消息开销做保守 Token 估算。发送请求前按输入和最大输出预留费用，同时按剩余费用收紧 `max_tokens`；成功后按返回用量或输出字节估算释放未用输出额度。流式输出包含推理片段。定时 AI 成果的路径和正文开销也纳入保守估算。

这些数字是本地估算，不是供应商账单；缓存折扣、特殊模型计费和供应商未遵守输出上限可能使实际账单不同。任务启动时固定单价，之后修改单价不会重新计算已执行任务。尚未开始调用的任务可在配置单价后恢复。无单价时可执行未设置成本上限的任务，费用显示“未计价”；启用费用上限则在调用前阻止执行。

每次模型调用、摘要调用或实际工具执行计 1 步；拒绝工具、等待审批、等待澄清不计步数。定时命令每次尝试计 1 步。请求发出前持久化步数和费用预留；失败、应用退出或结果未知时保留预留，避免漏算和重复调用绕过预算。

## 时间与暂停

时间累计上下文准备、模型和工具执行。人工等待、重试等待、应用关闭期间不计入执行时间。进行中的任务周期保存时间检查点，重启恢复保留之前的用量；异常退出会有最近一个检查点以内的计时误差。

模型调用和定时命令达到时间上限时停止等待，保留已保存结果；命令可能已产生部分操作，恢复前须检查成果。聊天中已启动的工具先达到已记录结果或原有超时，再暂停后续步骤，因此这类操作可能超过预算时间，预算不能撤销已产生的副作用。原有单次上下文 / 模型 300 秒、定时 AI 180 秒、命令 45 秒超时仍生效。

成本不足、步数耗尽、时间耗尽都会暂停。聊天使用 `awaiting_recovery` 并显示预算原因；定时任务使用 `budget_paused`，不会自动重试或产生同任务的新触发记录，直至用户处理。调整后用量保持不变；上限仍不够时恢复会被拒绝。待审批 / 澄清的聊天任务恢复后保留原等待步骤。

## 系统通知

通知由 Rust 后台在成功结果持久化后发送，不依赖聊天页面是否挂载，切换页面或最小化到托盘后仍可发出。每条成功任务最多尝试一次；重试的中间失败、预算暂停、取消不发完成通知。任务可单独关闭完成通知。

通知只包含任务 / 会话标题和完成提示，不包含正文或密钥。通知请求失败记录日志，不改变任务成功状态（插件异步提交，无法确认最终展示）；系统通知设置和免打扰可能影响展示。Windows 正式应用应使用安装版本验证名称与图标；开发运行的标识可能不同。接入依据：[Tauri 官方通知插件文档](https://v2.tauri.app/plugin/notification/)。

## 验证

Rust 测试覆盖费用预留与输出限制、无单价拦截、时间超限保留部分输出、步数暂停前无文件副作用、调整后继续且不清零、定时重试累计、暂停阻止新触发、记录重启持久化及通知去重 / 关闭。前端测试覆盖预算字段、未计价和累计用量、IPC 契约；浏览器测试使用模拟 Tauri 接口验证配置、模型单价、会话覆盖及暂停后的调整。已通过插件所用的 Windows 原生通知后端进行一次实际派发测试，返回成功；这不等于确认安装版本的名称、图标或系统弹窗可见性。
