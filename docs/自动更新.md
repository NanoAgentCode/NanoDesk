# 自动检查更新

主窗口启动 5 秒后检查一次，此后每 6 小时检查 GitHub 仓库 `NanoAgentCode/NanoDesk` 的最新稳定 Release。仅提示高于当前应用版本、且包含当前架构安装包的版本；忽略草稿和预发布版本。同一版本每次启动最多自动提示一次。

检查优先读取 `https://github.com/NanoAgentCode/NanoDesk/releases/latest/download/latest.json` 静态清单，不消耗 GitHub REST API 的共享 IP 请求额度。仅在清单返回 404 时回退到旧 Release API，以兼容未附带清单的历史版本；旧 API 仍可能限流。清单下载失败、格式损坏或服务端错误均显示检查失败，不作为“无更新”处理。静态清单仍需要能够访问 GitHub。

「系统设置 → 更新应用」显示已安装应用的当前版本，提供「更新日志」与「检查更新」入口。更新日志直接在设置页展开，可点击「收起日志」关闭；内容在构建时从仓库 `CHANGELOG.md` 内置，支持离线阅读，不会打开浏览器，仓库相对文档链接只显示文字。内置记录随安装版本更新；尚未安装的新版本说明由更新清单提供，并显示在更新提示窗口。手动检查期间按钮显示「正在检查…」并禁止重复点击。发现新版后复用下载弹窗（即使此前选择了稍后再说）；无可用更新时显示结果，网络或限流失败时显示错误并允许重试。手动检查不改变自动检查的周期。

弹窗显示版本号及更新说明。「下载更新」在应用内下载官方 Release 对应架构的安装包并显示已下载大小及进度；下载完成后显示「立即安装」，用户点击后启动安装程序并退出 NanoDesk；「稍后再说」关闭提示。下载或启动安装失败时可重试。下载及启动安装期间禁止关闭弹窗；不提供断点续传，下载失败会清理未完成文件。安装包保存在应用缓存 updates 目录，仅本次运行中成功下载的安装包可启动。检查失败（包括离线、超时、GitHub 限流）不打断聊天，下个周期重试。

发布时需同步维护 Cargo.toml、tauri.conf.json 和 package.json 中的版本号，创建正式 GitHub Release，并上传对应安装包，名称以 `_x64-setup.exe` 或 `_arm64-setup.exe` 结尾。仅推送 Git 标签或上传 Actions 构建产物不会触发更新提示。当前应用打包目标为 Windows NSIS，不会自动安装或重启应用，必须由用户点击「立即安装」。

打包脚本在 `.build/releases/v<版本>/windows-x64/` 导出安装包时，同时生成 `latest.json`，更新说明取自 `CHANGELOG.md` 对应版本。发布时必须把它与安装包一起上传到同一个正式 Release，标签须为 `v<版本>`。清单沿用 Release 字段：`tag_name`、`body`、`draft`、`prerelease`、`assets`（含 `name` 和 `browser_download_url`）。当前导出的清单只包含本次安装包；如发布多个架构，上传前需将各架构条目合并到同一个清单。旧客户端仍使用旧 API，需手动安装包含本修复的版本后才能使用静态清单。
